# 论文阅读 Backend 重建与 CUDA 配置收敛测试记录

时间：2026-03-13 19:40

## 目标

验证 backend rebuild 基线已经改善：

1. `backend/.dockerignore` 能过滤本地大目录
2. 本地默认 torch wheel 来源切到 CUDA
3. shell entrypoint 不再被 CRLF 污染

## 现状证据

已确认：

- `backend/.dockerignore` 原本仅有 `models/`
- `backend/.venv-incremental` 单目录约 `5.5G`
- `.env` 中当前为 CPU wheel：
  - `TORCH_INDEX_URL=https://download.pytorch.org/whl/cpu`
- backend 容器曾因 `docker-entrypoint.sh` 的 CRLF shebang 失效而启动失败

## 本轮计划验证

1. 配置检查
   - `backend/.dockerignore`
   - `.env`
   - `.env.example`
   - `.gitattributes`

2. 文本/行尾检查
   - `backend/docker-entrypoint.sh` 不应再出现 `^M`

3. 轻量验证
   - 不在本轮立刻跑完整 backend rebuild
   - 先保证重建前置条件正确，再择机执行一次真正 rebuild

## 风险说明

- 当前 backend 完整 rebuild 在 `/mnt/d` + 大 build context 下成本很高
- 因此这轮优先验证“重建条件是否正确”，而不是立刻跑完整成本高的全量构建

## 已执行验证

1. 配置检查
   - `backend/.dockerignore` 已改成 allowlist 风格
   - `.env/.env.example` 中 `TORCH_INDEX_URL` 已切到 `cu121`
   - `.gitattributes` 已新增 `*.sh text eol=lf`

2. 行尾检查
   - `sed -n '1,20p' backend/docker-entrypoint.sh | cat -vet`
   - 结果：无 `^M`
   - `git check-attr eol -- backend/docker-entrypoint.sh`
   - 结果：`eol: lf`

3. 轻量 build context 探测
   - 旧探测：`transferring context: 2.03GB`
   - 新探测：`transferring context: 14.60MB`
   - 结论：backend rebuild 成本已从“传巨量本地开发目录”转为“主要耗在真正镜像构建和 CUDA 轮子下载”
