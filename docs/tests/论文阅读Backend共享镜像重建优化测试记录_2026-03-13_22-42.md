# 论文阅读 Backend 共享镜像重建优化测试记录

时间：2026-03-13 22:42

## 目的

验证 backend 系服务改为共享单一镜像后：

- backend-only 重建路径更清晰
- 不再为同构服务重复声明 build
- 不影响 `backend / codelab-runner / mcp_*` 的运行命令差异

## 变更前已确认基线

### build context

- 旧探测：约 `2.03GB`
- 当前 `.dockerignore` allowlist 后：约 `14.60MB`

### CUDA 配置

- `.env`：`TORCH_INDEX_URL=https://download.pytorch.org/whl/cu121`
- `.env.example`：`TORCH_INDEX_URL=https://download.pytorch.org/whl/cu121`

### shell 行尾

- `backend/docker-entrypoint.sh` 已为 `LF`
- `git check-attr eol -- backend/docker-entrypoint.sh` 返回 `eol: lf`

## 本轮计划验证

1. Compose 中只有 `backend` 保留 `build`
2. `codelab-runner / mcp_web / mcp_literature` 改用共享镜像
3. `docker compose config` 可正常展开
4. backend-only 重建命令仍能带上 `TORCH_INDEX_URL`

## 结果

### Compose 共享镜像收敛

- `backend`
  - 保留 `build`
  - 新增 `image: research-assistant-backend:latest`
- `codelab-runner`
  - 移除 `build`
  - 改为 `image: research-assistant-backend:latest`
- `mcp_web`
  - 移除 `build`
  - 改为 `image: research-assistant-backend:latest`
- `mcp_literature`
  - 移除 `build`
  - 改为 `image: research-assistant-backend:latest`

### 配置验证

- `docker compose config`：通过
- `rg -n "research-assistant-backend:latest|build:" docker-compose.yml`
  - backend 系服务只保留一处 backend build owner
  - 同构服务改为共享镜像
- `docker compose -f docker-compose.yml -f .github/docker-compose.ci.yml config`
  - 通过
  - backend build args 显式为 `TORCH_INDEX_URL=https://download.pytorch.org/whl/cpu`
  - 本地与 CI 的 torch wheel 默认值已分流

### 额外发现

- `backend/Dockerfile` 本身已经支持 `ARG TORCH_INDEX_URL`
- `docker-compose.yml` 原本就已把 `TORCH_INDEX_URL` 从 `.env` 透传给 backend build
- 之前直接运行 `docker buildx build` 看到 CPU index，只是因为探测命令没有传 build arg

### 当前结论

- backend build context 已从约 `2.03GB` 降到约 `14.60MB`
- backend 系服务镜像复用已完成
- CI/nightly 不会跟随本地默认值误装 CUDA torch wheel
- 后续正式 backend rebuild 的主要成本将集中在 `cu121` torch wheel 下载与安装，而不是上下文传输或重复 build
- backend 与 `codelab-runner` 现已共同运行在同一镜像 digest 上：
  - `sha256:9788a3de7010c0fe338040c4ba6f9d9a33f7bcb2acff23ace376404b226d66bc`
