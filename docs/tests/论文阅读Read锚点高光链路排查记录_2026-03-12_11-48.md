# 论文阅读 `/read` 锚点高光链路排查记录

时间：2026-03-12 11:48  
范围：`/literature/78/read?page=4&kb=84`、`/literature/78/read?page=7&kb=84`、`/literature/85/read?page=1&kb=84`

## 结论

这次排查把两个问题分开了：

1. `78/page=4` 与 `78/page=7`
   - 后端返回的 paragraph anchor 合同是同一类，不存在 `page=7` 特制、`page=4` 缺字段的情况。
   - 两页的 `ParagraphProse` 都带：
     - `capabilities: ["copy", "drag_markdown", "inline_query", "jump_anchor"]`
     - `coord_version = anchor_v2`
     - `anchor_confidence = 0.92`
     - `bbox_hint`
     - `geometry.source = "bbox_rebuilt"`
   - 因此，`page=4` hover/click 没有出现高光，不能先归因为后端没产出 paragraph anchor。

2. `85/page=1`
   - 这是明确的后端几何失真问题。
   - 多个 paragraph anchor 的 `bbox_hint` 被重建成了极窄的竖条，例如：
     - `x0 = 16.34, x1 = 36.34, top = 337.68, bottom = 568.76`
   - 这会直接导致证据高光错位。
   - 该问题主要落在 `bbox_rebuilt` 路径，而不是前端 hover 行为。

## 进一步判断

### 关于 `78/page=4`

已确认以下事实：

- paragraph anchor 在后端 payload 里存在
- `jump_anchor` capability 存在
- `bbox_hint / geometry` 存在
- 这些字段与 `78/page=7` 是同一类合同

所以，`78/page=4` “hover 没反应、点击证据没弹高光” 不能再笼统说成“后端没产高光”。  
它更像是：

- 前端在 `reading_flow_stack` / paragraph-heavy 布局上的交互链路问题，或
- 运行时消费了后端合同，但在实际 hover/click 路径里没有把它正确表现出来

### 关于 `85/page=1`

这是后端问题，而且是几何重建问题，不是单纯 UI 问题：

- `bbox_rebuilt` 在 metadata-heavy / title-like 页面上会产出失真的窄条 bbox
- 这种 bbox 会直接把高光画错

## 建议后续动作

1. 对 `/read` paragraph highlight 分两类跟进，不再混为一谈。
2. `78/page=4`
   - 继续查 hover/click 运行时链路，不要再重复怀疑“后端没 anchor”。
3. `85/page=1`
   - 优先修 `bbox_rebuilt` 在 title / cover / author-heavy 页面上的失真问题。
   - 同时推进 page archetype gating，避免首页继续走普通正文页的 compose/highlight 假设。
