# 论文阅读 Read 内联追问提速与局部回答收敛测试记录

时间：2026-03-15 16:35

## 目标

验证 `/read` 的 `+ 段落追问` 满足：

- 优先读取已有 compose cache
- 真流式输出 token
- prompt 不再过度保守拒答
- `disabled` 事件前端有明确反馈

## 计划验证项

1. inline query 预处理优先走 `get_latest_cached_payload_only(...)`
2. 没有 cache 时仍能回退到 `build_or_get_composed_payload(...)`
3. inline query prompt 不再写死“证据不足请去右侧询问”作为主路径
4. SSE 可在 answer 未完整生成前先返回 token
5. frontend 收到 `disabled` 时会有用户可见结果

## 手动验证建议

- 在已经生成过的 `/read` 页面，对 `ParagraphProse` 点击 `+ 段落追问`
  - 预期首 token 更快出现
- 问局部问题（例如“这里说的原因是什么”）
  - 预期优先给局部回答，而不是动辄拒答
- 对无锚点/无 block 的节点点追问
  - 预期能看到显式不可用提示，而不是无反馈
