# hybrid 初步评估

- 日期：`2026-03-30`
- 阶段：`retrieval ablation`
- 状态：`done`

## 问题

当前知识库搜索主链支持：

- `dense-only`
- `dense + FTS + RRF` hybrid

实现位置：

- [knowledge.py](/mnt/d/codefield/agent-platform/research-assistant/backend/app/api/knowledge.py)
- [hybrid_retrieval_service.py](/mnt/d/codefield/agent-platform/research-assistant/backend/app/services/hybrid_retrieval_service.py)

需要判断：

- hybrid 是否值得作为默认增强项
- hybrid 提升的是召回、顶部排序，还是两者都提升

## 当前观察

基于公开 `BEIR / SciFact` 小规模子集的当前结果：

- `dense-only`
  - `20 queries / 200 corpus`
  - `NDCG@10 = 0.94434`
  - `Recall@10 = 1.0`
  - `MRR@10 = 0.92667`

- `dense + hybrid`
  - `20 queries / 200 corpus`
  - `NDCG@10 = 0.94599`
  - `Recall@10 = 0.95`
  - `MRR@10 = 0.95`

## 暂定判断

当前第一版信号是：

- hybrid 可能改善顶部排序
- hybrid 不一定改善 `Recall@10`
- 当前还不能据此直接决定是否默认开启

换句话说：

- hybrid 更像“排序增强候选”
- 不是已经证明的“召回增强默认项”

## 当前决定

- hybrid 单因素消融已经完成
- 当前信号偏向“提升顶部排序”，不偏向“稳定提升召回”
- 默认是否开启，继续留到组合消融阶段统一决策

## 等待后续消融回答的问题

1. 在更大公开集子集上，hybrid 对 `NDCG / Recall / MRR` 的趋势是否稳定
2. hybrid 是否主要改善顶部排序，而不是主召回
3. 如果 rerank 也开启，hybrid 的边际收益还剩多少
4. 当前系统默认值应收敛到：
   - `dense-only`
   - `dense + hybrid`
   - 或按知识库类型切换

## 暂不执行的动作

- 不立即修改 `enable_hybrid_retrieval` 默认值
- 不立即调整 `RRF` 参数为新的默认策略
- 不立即把 hybrid 写成推荐结论

## 后续落点
