# LoRA 微调效果报告 2026-04-26

## 结论

本地目录中已经存在 Qwen LoRA 微调训练产物和评估结果，覆盖三条任务线：

- `qwen-action`：判断 PDF 行/块后处理动作，典型标签为 `KEEP / REPAIR / OCR`，后续版本加入 `DROP`。
- `qwen-clean`：文本清洗输出生成，关注 exact match、文本相似度和过度修正率。
- `qwen-chunk`：分块边界判断，典型标签为 `NEW_CHUNK / JOIN_PREV`。

这些结果目前保存在 `backend/models/` 下。该目录被 `.gitignore` 忽略，因此模型权重、训练日志、评估 summary 都没有进入 Git。本文档只整理本地已有 summary 指标，适合作为可提交的效果摘要。

## Action 任务效果

Action 任务用于判断文本行或块的后续处理动作。不同版本的数据标签体系不完全一致：早期是 `KEEP / REPAIR / OCR`，v4 drop 版本是 `KEEP / REPAIR / DROP`。

### 代表性结果

| 评估项 | 数据集 | 样本数 | Accuracy | Macro F1 | 说明 |
| --- | --- | ---: | ---: | ---: | --- |
| base raw on v4 drop | `final_2k_plus_manual_qwen_hard_v4_base_boundary_drop/action_sft.jsonl` | 250 | 0.292 | 0.216 | 未微调基座，严重偏向 `DROP`，且不预测 `REPAIR` |
| LoRA v4 drop | 同上 | 250 | 0.832 | 0.783 | 当前 DROP 语义下的主要可用版本 |
| LoRA v3 keep/repair | `final_2k_plus_manual_qwen_hard_v3_keep_repair/action_sft.jsonl` | 246 | 0.890 | 0.837 | `KEEP / REPAIR / OCR` 体系下表现较稳 |
| runtime merged v1 on v3 | `final_2k_plus_manual_qwen_hard_v3_keep_repair/action_sft.jsonl` | 246 | 0.911 | 0.870 | 旧 runtime merged v1 在 v3 集合上分数最高 |
| runtime merged v1 on v4 drop | `final_2k_plus_manual_qwen_hard_v4_base_boundary_drop/action_sft.jsonl` | 250 | 0.804 | 0.614 | 旧模型不适配 `DROP`，DROP recall 很低 |

### v4 drop 详细结果

数据源：

```text
backend/models/training/runs/eval_qwen_action_base_v4_drop_on_v4_drop/summary.json
```

整体指标：

```text
eval_rows = 250
accuracy = 0.832
macro_f1 = 0.7832471920848499
```

分类指标：

| Label | Precision | Recall | F1 | Support |
| --- | ---: | ---: | ---: | ---: |
| KEEP | 0.849 | 0.913 | 0.880 | 160 |
| REPAIR | 0.766 | 0.750 | 0.758 | 48 |
| DROP | 0.839 | 0.619 | 0.712 | 42 |

分布：

```text
pred_distribution = KEEP 172, REPAIR 47, DROP 31
gold_distribution = KEEP 160, REPAIR 48, DROP 42
```

判断：

- LoRA 明显修复了 base raw 的动作识别崩溃问题。
- v4 drop 版本能够预测 `DROP`，但 `DROP recall=0.619`，仍有漏删风险。
- 如果生产路径已采用 `DROP` 标签体系，应优先使用 v4 drop 或后续兼容版本，不应继续使用旧 `OCR` 体系模型直接承担 drop 决策。

## Chunk 任务效果

Chunk 任务用于判断当前段落是否开启新 chunk，标签为 `NEW_CHUNK / JOIN_PREV`。

### v5 context paragraph 对比

未微调基座：

```text
source = backend/models/training/runs/eval_qwen_chunk_base_raw_on_v5_context_paragraph/summary.json
eval_rows = 173
accuracy = 0.9017341040462428
macro_f1 = 0.47416413373860183
pred_distribution = NEW_CHUNK 0, JOIN_PREV 173

```

LoRA checkpoint-500：

```text
source = backend/models/training/runs/eval_qwen_chunk_v5_checkpoint500_on_v5_context_paragraph/summary.json
eval_rows = 173
accuracy = 0.9479768786127167
macro_f1 = 0.8492593668312518
pred_distribution = NEW_CHUNK 16, JOIN_PREV 157
gold_distribution = NEW_CHUNK 17, JOIN_PREV 156
```

对比：

| 模型 | Accuracy | Macro F1 | NEW_CHUNK Precision | NEW_CHUNK Recall | NEW_CHUNK F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Base raw | 0.902 | 0.474 | 0.000 | 0.000 | 0.000 |
| LoRA checkpoint-500 | 0.948 | 0.849 | 0.750 | 0.706 | 0.727 |

混淆矩阵：

```text
labels = NEW_CHUNK, JOIN_PREV
matrix =
  NEW_CHUNK: [12, 5]
  JOIN_PREV: [4, 152]
```

判断：

- Base raw 的 accuracy 看起来高，但实际完全不预测 `NEW_CHUNK`，属于类别不均衡下的虚高。
- LoRA 后 macro F1 从 `0.474` 提升到 `0.849`，这是本轮最明确的有效提升。
- `NEW_CHUNK` 的 recall 为 `0.706`，仍可能漏掉部分新段落边界；如果用于知识库切分，应继续保留规则/阈值兜底。

## Clean 任务效果

Clean 任务用于生成清洗后的文本。

数据源：

```text

```

整体指标：

| 指标 | 数值 |
| --- | ---: |
| eval_rows | 189 |
| exact_match | 0.8835978835978836 |
| text_similarity | 0.9978443953223259 |
| changed_rows | 32 |
| changed_exact | 0.53125 |
| changed_similarity | 0.9912102473783461 |
| unchanged_rows | 157 |
| unchanged_exact | 0.9554140127388535 |
| over_correction_rate | 0.044585987261146494 |

判断：

- 整体文本相似度非常高，说明模型输出通常不会大幅偏离目标文本。
- changed rows 的 exact match 只有 `0.531`，说明在真正需要修复的样本上，完全一致仍有明显空间。
- over correction rate 为 `0.045`，可接受但不能忽略；生产上应继续配合规则检查，避免模型对本来正确的文本过度改写。

## 风险与限制

1. 当前报告来自本地 ignored 目录，不是 CI 自动生成结果。
2. 各版本评估集不完全一致，不能把所有分数直接横向排名。
3. Action 标签体系发生过变化，`OCR` 与 `DROP` 版本不能混用。
4. Chunk base raw 的 accuracy 虚高，必须优先看 macro F1 和 `NEW_CHUNK` 指标。
5. Clean 任务缺少更大规模人工评估，exact match 不能完全代表语义可接受性。
6. 目前还没有看到线上 A/B 或真实 PDF 入库端到端收益统计。

## 建议

短期建议：

- 将本报告纳入 Git，保留可追溯摘要。
- 不提交 `backend/models/` 下的权重和大日志。
- 如果要上线 action drop 语义，优先验证 `qwen_action_lora_base_v4_drop`。
- 如果要上线 chunk 边界，优先验证 `qwen_chunk_lora_v5_context_paragraph`，并保留规则兜底。
- Clean 模型建议先作为候选修复器，不要无条件覆盖原文。

后续补充评估：

- 对真实 PDF 入库样本做端到端 ablation：规则链 vs LoRA 辅助链。
- 统计 chunk 命中率、RAG 引用质量、人工标注错误率变化。
- 对 action 的 `DROP` 做高召回优先评估，避免该删未删。
- 对 clean 做人工抽样，区分“格式不同但语义正确”和“真正错误”。
