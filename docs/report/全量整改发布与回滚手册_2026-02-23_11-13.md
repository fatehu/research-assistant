## 四、故障定位优先级

1. 先看容器状态与日志（`ps/logs`）。
2. 再看 checks 脚本输出与 CI 失败步骤。
3. 最后再定位代码逻辑问题，避免环境误判。

## 五、运维常见问题

1. `open //./pipe/dockerDesktopLinuxEngine` 报错
- 含义：Docker Desktop Linux 引擎未启动。

2. 后端 pytest 报 `ModuleNotFoundError: loguru/fastapi`
- 含义：本地 Python 环境缺少后端依赖。
- 处置：在项目虚拟环境安装 `backend/requirements.txt` 后重试。
