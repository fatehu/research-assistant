# 论文阅读模块 Agentic PDF直读工具与自主决策修正说明（2026-02-16 06:13）

## 1. 目标
- 为论文询问 Agent 增加独立 `paper_read` 工具，支持直接读取当前论文 PDF。
- 将 Agentic 询问从“强制先入库”改为“Agent 自主选择策略”：可在 `knowledge_search` 与 `paper_read` 之间动态决策。
- 保持引用编号跨多次工具调用稳定，避免多轮对话来源编号冲突。

## 2. 变更范围（白名单）
- `backend/app/api/literature.py`

## 3. 关键实现
1. 新增/完善 `paper_read` 工具接入
- 工具名：`paper_read`
- 能力：直接读取当前论文本地 PDF，按 query 关键词命中度排序返回页级片段。
- 输出：`[来源X]` + 文档名 + 页码 + 片段，`score_source=paper_read`。

2. 统一来源编号分配器
- 引入共享 `LiteratureSourceIndexAllocator`。
- `knowledge_search` 与 `paper_read` 共用同一编号分配器，避免 `[来源X]` 重号。

3. 调整 `literature_ask` 入口门禁
- 旧逻辑：无 `ready_links` 直接 409。
- 新逻辑：当 `mode=agentic` 且 `scope=paper` 且本地 PDF 存在时，允许无入库直接提问（PDF直读路径）。
- 其余场景（如 classic / collection 无 ready）仍保持 409 保护。

4. Agent 观测汇聚修正
- 旧逻辑只收集 `knowledge_search` 的来源。
- 新逻辑同时收集 `knowledge_search` + `paper_read` 结果，统一进入 sources。

5. System Prompt 改为“策略自主”
- 去掉硬编码流程导向。
- 明确：由 Agent 根据问题质量/证据/时效性自行决定工具与调用次数。

## 4. 用户可感知变化
- 当前论文未入库时，`Agentic` 模式下只要本地 PDF 可用即可回答。
- 回答来源会显示来自 PDF 直读的页级片段，不再只依赖知识库。
- 多轮提问中来源编号更稳定，不易出现引用编号冲突。

## 5. 回滚与兼容
- 兼容现有 API 结构，不新增破坏性字段。
- 若需回滚，仅撤销 `literature.py` 本次变更即可恢复“必须入库后询问”的旧行为。

## 6. 风险与后续
- `paper_read` 当前是页级关键词匹配，语义召回质量不等价于向量检索。
- 后续可增强：页内段落级切片、结构化标题锚点、跨论文多 PDF 直读工具。
