# 论文阅读 `/read` DocMind 整页尺寸恢复说明

## 结论

这次 `/read` hover / pinned evidence 整体右下偏移，根因不是前端 hover 本身，也不是 DocMind 没给真值，而是后端给 `layout_uid_v1` anchor 写入了错误的整页尺寸。

## 根因

`layout_uid_v1` anchor 的 `geometry.page_width/page_height` 与 `bbox_hint.page_width/page_height`，在 `page_grounding_v1.page_image.width/height` 缺失时，会退化为：

- 这一页出现过的最大 `x`
- 这一页出现过的最大 `y`

这实际上只是“内容边界”，不是“整页尺寸”。

例如运行态真实值：

- 错误值：`1227 x 1844`
- DocMind 页图真实尺寸：`1483 x 1920`

前端 evidence preview 再按这个错误尺寸缩放到 PDF.js viewport，就会稳定向右下放大。

## 修复

1. `page_grounding_v1` 在构建时，如果 `docmind_structure.page_image_width/page_image_height` 缺失：
   - 优先读取 DocMind 页图本身的真实尺寸
   - 本地路径就地读取
   - 远程 URL 则抓取图片头并用 Pillow 解析尺寸

2. `layout_uid_v1` anchor 继续使用：
   - `uniqueId -> blocks[].pos`
   - 但整页缩放基准改回真实 DocMind 页图尺寸

3. compose engine 升到 `reader_compose_v9`
   - 避免旧 `v8` cache 继续把错误尺寸返回给前端

## 运行态证据

修复前的 live payload：

- `engine_version = reader_compose_v8`
- `geometry.page_width/page_height = 1227 x 1844`

修复后的 live payload：

- `engine_version = reader_compose_v9`
- `geometry.page_width/page_height = 1483 x 1920`
- `bbox_hint.page_width/page_height = 1483 x 1920`

## 原则

后续 `/read` 的 evidence preview 仍然坚持：

- 高光来源是 DocMind 真值
- 最小溯源单位是 `uniqueId`
- 高光几何优先使用 `uniqueId -> blocks[].pos`
- 整页缩放必须使用真实页图尺寸，不能再用内容边界近似
