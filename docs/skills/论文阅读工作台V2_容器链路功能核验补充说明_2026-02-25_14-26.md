# 论文阅读工作台 V2 容器链路功能核验补充说明（2026-02-25 14:26）

## 1. 目的
- 在真实 Docker 运行环境中补齐此前未完成的阅读器功能核验，确认 `composed` 链路、节点级动作、内联问答、预读能力可用。
- 使用 PLOS 样例论文（`10.1371/journal.pdig.0000198`）进行端到端验证，避免仅依赖单元测试结论。

## 2. 本次核验覆盖范围
- 容器可用性与服务健康：
  - `backend`、`frontend`、`postgres`、`redis`、`codelab-runner`
- 阅读器 API 链路：
  - `POST /api/v1/literature/papers/{paper_id}/reader/composed/stream`
  - `POST /api/v1/literature/papers/{paper_id}/reader/composed/prefetch`
  - `POST /api/v1/literature/papers/{paper_id}/reader/composed/node/action`
  - `POST /api/v1/literature/papers/{paper_id}/reader/composed/inline-query/stream`
  - `POST /api/v1/literature/papers/{paper_id}/reader/generative/stream`（对照）
- 数据准备链路：
  - 用户注册/登录
  - 保存论文元数据
  - 下载 PDF 到本地缓存

## 3. 核验方法
- 为避免外部学术搜索限流（Semantic Scholar 429），改用“手工构造 PLOS 元数据 + 直链下载官方 PDF”策略。
- 通过流式 SSE 消费器验证事件顺序、事件计数和 `done.payload` 结构。
- 对 `ui_plan.components` 做扁平化检查，提取 `SectionHeading/PaperHeaderCard` 标题与质量报告字段。
- 对同一节点执行 `degrade` 与 `regenerate` 动作，验证 overlay 持久化行为。

## 4. 关键结果
- 已确认可用：
  - `composed stream` 返回 `start -> plan_draft -> plan_patch* -> quality* -> assets -> done`
  - `prefetch` 返回 `queued/skipped`
  - `node/action` (`degrade` 与 `regenerate`) 返回 `patch_type=node_replace` 且 `overlay_saved=true`
  - `inline-query/stream` 返回 `start/token/sources/done`
  - `generative stream` 对照链路可正常返回结构化 `sections/blocks`
- 已暴露问题（需继续修）：
  - 第 1 页标题仍存在断裂：`for AI-assisted medical education using large` 与 `language models` 被拆成独立 heading。
  - `quality_report.title_integrity_ok=false`
  - `quality_report.anchors_valid=false`
  - `validation_errors` 包含 `invalid anchor range in heading_6`
  - 页内质量分偏低（示例：page1 `overall=0.53`，page2 `overall=0.62`）

## 5. 结论
- “能力可用性”已打通：接口、流式协议、节点操作、内联问答、预读均可运行。
- “阅读质量”仍不达标：当前主要瓶颈集中在标题完整性与锚点合法性，与你反馈的“标题被拆”“结构不自然”一致。
- 后续优化应优先修复：
  1. heading 切分与合并规则（避免标题跨行误拆）
  2. anchor range 计算与校验（消除 invalid anchor）
  3. 质量门控策略（`title_integrity_ok/anchors_valid` 未满足时自动触发更强修复）
