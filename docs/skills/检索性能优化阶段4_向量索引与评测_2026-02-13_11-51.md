# 检索性能优化阶段4_向量索引与评测_2026-02-13_11-51

## 1. 本次目标
在不切换生产主维度的前提下，建立向量检索调优闭环：
- 动态 `ef_search`
- 1024 vs 512 评测能力
- 可复用评测脚本与样例数据

## 2. 使用技术
- HNSW 检索参数自适应：`resolve_ef_search(total_chunks, dimension)`
- 配置驱动：
  - `PGVECTOR_HNSW_EF_SEARCH_MODE`
  - `PGVECTOR_HNSW_EF_SEARCH_MIN`
  - `PGVECTOR_HNSW_EF_SEARCH_MAX`
- 评测脚本：`app.maintenance.eval_retrieval_recall`
  - 指标：`recall@k`、`MRR`、平均延迟
  - 输出：Markdown 报告

## 3. 关键改动
- `backend/app/services/vector_search_tuning.py`
  - 新增 `resolve_ef_search(total_chunks, dimension)`
  - 保留并复用 `apply_hnsw_ef_search(...)`
- `backend/app/api/knowledge.py`
  - 在检索前计算语料规模与向量维度
  - 使用 `resolve_ef_search` 动态设置 `hnsw.ef_search`
  - 日志增加 `ef_search` 与 `corpus_size`
- `backend/app/services/agent_tools.py`
  - Tool 侧同步动态 `ef_search`
  - 日志增加 `ef_search` 与 `corpus_size`
- `backend/app/maintenance/eval_retrieval_recall.py`
  - 新增评测脚本（1024/512 对比）
- `backend/tests/data/retrieval_eval_cases.sample.json`
  - 新增评测用例模板
- `backend/tests/test_vector_search_tuning.py`
  - 增加 adaptive 模式边界与维度偏置测试

## 4. 达成效果
- `ef_search` 不再固定为单值，可随语料规模与维度动态变化。
- 已具备产出 1024 vs 512 对比报告能力，为后续是否切维度提供数据依据。

## 5. 怎么使用
- 动态检索参数默认开启：`PGVECTOR_HNSW_EF_SEARCH_MODE=adaptive`
- 评测命令示例：
  - `python -m app.maintenance.eval_retrieval_recall --cases backend/tests/data/retrieval_eval_cases.sample.json --top-k 10 --output docs/test/阶段4检索评测报告_xxx.md`

## 6. 风险与边界
- 当前样例用例使用占位 chunk_id，评测值主要用于链路验证；
  正式结论需替换为真实标注用例。
- 首次评测会触发本地 embedding 模型加载，存在冷启动耗时。
