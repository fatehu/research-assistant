# 全量整改阶段06：017 迁移与历史状态冲突修复实施说明

- 时间：2026-02-23 10:52
- 阶段目标：新增 Alembic `017` 迁移，归一化历史冲突状态并保留审计记录。
- 关联 commit：`feat(migration): 新增017迁移并处理历史冲突数据`

## 本阶段改动
1. 新增迁移：`backend/alembic/versions/017_status_normalization_and_conflict_cleanup.py`。
2. 归一化对象：
   - `documents.status` -> `pending | processing | completed | failed`
   - `paper_knowledge_links.status` -> `pending | processing | ready | failed`
3. 处理策略：
   - 对 `running/queued/success/done/timeout/cancelled/error/NULL/未知值` 做统一映射。
   - 对映射为失败且原 `error_message` 为空的数据，补写“状态迁移归一化: 原状态=...”。
4. 新增审计表：`status_migration_audit_017`，记录两张表的归一化行数与说明。
5. `downgrade` 策略：只移除审计表，不回滚已归一化状态（前向数据治理，避免不确定逆变换）。

## 设计取舍
1. 以“数据可用与可追溯”为优先：先归一化再审计，而不是尝试不可靠逆向还原。
2. 迁移 SQL 采用批量 `UPDATE ... RETURNING` 统计，避免应用层逐行迁移。

## 风险与回滚
1. 风险：中。状态值会被前向修正，不可自动恢复原脏值。
2. 回滚：结构层面可回滚审计表；数据层面建议从备份恢复（如必须）。

## 效果感知
1. 历史状态冲突在数据库层一次性收敛，避免运行时状态分叉。
2. 归一化规模可通过 `status_migration_audit_017` 直接审计。
