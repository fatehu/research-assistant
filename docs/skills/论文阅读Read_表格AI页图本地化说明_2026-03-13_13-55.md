## 背景

`/read` 表格 AI logical-row 重建已经真实进入 live payload，但正常页面访问时仍可能 fallback。

已确认根因：

- `page_grounding_v1.page_image.path` 在 live payload 中为空
- 只剩远程 `url`
- `_invoke_single_agent_model(...)` 因为没有本地图片文件，无法走 DashScope 本地多模态路径
- 最终退回 `image_url`
- provider 返回：`Failed to download multimodal content`

## 本次目标

只补一个 end-to-end 缺口：

- 如果 `rendered_page_image_path` 为空，但 `rendered_page_image` 是安全远程图片 URL
- 则把页图下载到本地缓存
- 再按本地图片路径走 DashScope 多模态

## 实现

- `_build_page_grounding_v1(...)` 继续在 grounding 阶段优先把 `docmind_structure.page_image_url` 落到：
  - `/app/uploads/reader_page_assets/paper_<id>/grounding_pages/page_<n>.<ext>`
- `_invoke_single_agent_model(...)` 新增 prompt 级兜底：
  - 若 `rendered_page_image_path` 为空
  - 但 `rendered_page_image` 是安全 `http/https` URL
  - 则再把它缓存到：
    - `/app/uploads/reader_page_assets/prompt_images/<sha>.<ext>`
  - 然后强制通过 `DashScopeMultimodalService.collect_local_file_uris(...)` 走 `file://...`
- `COMPOSE_ENGINE_VERSION` 升到 `reader_compose_v11`
  - 避免旧 `v10` cache 掩盖 live 修复结果

## 运行态结果

- fresh `/api/v1/literature/papers/85/reader/composed` 请求已实际跑通
- backend 日志中不再出现：
  - `Failed to download multimodal content`
- 实际返回：
  - `engine_version = reader_compose_v11`
  - `build_mode = compose_agent_layout_uid_v1`
  - `TablePanel.props.reconstruction_mode = ai_logical_rows`
  - `logical_rows = 13`
- cached payload 中已能看到本地 grounding 页图：
  - `page_grounding_v1.page_image.path = /app/uploads/reader_page_assets/paper_85/grounding_pages/page_7.png`

## 边界

不改：

- `/read` 表格 AI prompt
- logical row validator
- evidence/highlight 主链
- `/experience` 相关逻辑

## 回退边界

如果这轮导致 live 请求不稳定，只回退：

- `_ensure_local_prompt_image_path(...)`
- `_invoke_single_agent_model(...)` 里对远程页图的本地化分支

不要回退：

- `reader_compose_v10`
- live payload 中的 `logical_rows`
