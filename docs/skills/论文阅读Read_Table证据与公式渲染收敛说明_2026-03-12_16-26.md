# 论文阅读 Read Table 证据与公式渲染收敛说明

时间：2026-03-12 16:26

## 背景

`/read` 已经切到 `layout_uid_v1` 默认主链，但两类节点仍然明显不稳：

1. `TablePanel`
   - DocMind `cells[]` 真值已经在 `page_grounding_v1` 中保留下来。
   - 但 contract 归一化时丢掉了 `table_cells`，前端只能退回扁平 `matrix/rows`。
   - 行级证据 anchor 还带着基于行局部 polygon 推出来的伪 `page_width/page_height`，导致 evidence 裁图缩放偏移。
   - `TablePanel` 顶部显式 `证据 / 预览` 操作被弱化，用户只能依赖行 hover 或 ActionBar popover。

2. `EquationBlock`
   - 后端把公式主体和 trailing `where ...` 说明揉成一串。
   - 前端只是原样输出字符串，没有 KaTeX，也没有把原公式图当成稳定证据显示。

## 本轮目标

- 让 `/read` 的表格继续走 deterministic materialization，但不再丢 `table_cells`。
- 让表格行证据直接使用 `uniqueId/cell polygon` 的几何，不再伪造局部页宽高。
- 恢复表格显式证据入口。
- 让公式块至少具备：
  - KaTeX 渲染
  - 原公式证据图
  - `where ...` 说明单独展示

## 设计决策

### 1. TablePanel contract 补齐 `table_cells`

`TablePanel` 现在同时保留三层数据：

- `table_cells`
  - 来源：DocMind `cells[]`
  - 用途：优先重建 HTML table 的真实行列结构
- `matrix/headers/rows`
  - 用途：兼容旧渲染和降级
- `row_evidence`
  - 用途：行级 hover / click 证据预览

这样做的好处是：

- 真值链保留在 `table_cells`
- 旧 UI 不会立刻失效
- 后续做 `rowspan/colspan` 时不需要再回头补 DocMind 真值

### 2. 行级证据 anchor 不再写伪 page dimensions

之前 `row_evidence.anchor.geometry.page_width/page_height` 与 `bbox_hint.page_width/page_height`
是用“该行 polygon 的最大 x/y”凑出来的。

这会把“行局部坐标范围”误当成“整页坐标范围”，导致 evidence image 缩放偏移。

本轮改成：

- 行级 evidence 继续保留 polygon/bbox
- 但 `page_width/page_height` 置空
- 前端裁图时退回 PDF viewport 的真实尺寸

### 3. TablePanel 恢复显式 `证据 / 预览`

`TablePanel` 仍保留 `ActionBar`，但额外恢复顶部显式按钮：

- `证据`
- `预览`
- `导出CSV/Markdown`

这样即使用户不 hover 行，也能直接回到整表 evidence。

### 4. EquationBlock 改成 “KaTeX + 原图证据” 双轨

公式块不再只输出 OCR/LaTeX 字符串。

当前策略：

- 后端 `_build_layout_uid_equation_props(...)`
  - 拆出 trailing `where ...`
  - 拆出尾部 `(1)` 这类 label
- 前端 `EquationBlockNode`
  - 先调用 `resolveAnchorPreviewImage(...)` 显示原公式证据图
  - 再用 `react-markdown + remark-math + rehype-katex` 渲染公式

这一步并不假设 OCR 已经完美。
即便公式转录还不够好，用户也能看到正确的原图证据。

## 2026-03-12 17:00 运行态补充

这轮又补了一层运行态收口，原因是：

- `page_grounding_v1` 内部已经有 `table_cells`
- 但 API schema 会把 `layout_atoms[].table_cells` 和 `evidence_map[].table_cells` 吞掉
- 旧 `reader_compose_v6` cache 也会让页面继续读到“半新半旧”的表格结果

所以补做了两件事：

- 给 `ReaderGroundingLayoutAtom` 和 `ReaderGroundingEvidenceEntry` 正式加上 `table_cells`
- 把 compose engine 升到 `reader_compose_v7`

这层收口后的运行态证据是：

- `engine_version = reader_compose_v7`
- `table_atom_cells = 106`
- `evidence_cells = 106`
- `table_panel_source_atom_ids = ["5a8d08bf5c30c80ab57560215c225bbe"]`
- `table_panel_cell_evidence = 106`

也就是：

- 表格主证据只指向表体 layout，不再混入 `table_caption`
- `cell_evidence` 已经真正进入 API 返回，而不只是内部对象里存在
- `ActionBar` 里的“证据”菜单也必须接受 `coord_version = layout_uid_v1`
  - 之前它只接受 `anchor_v2`
  - 这会导致表格顶部按钮可用，但 `...` 菜单里只剩“复制 / 拖拽”
  - 当前已放宽为同时接受 `anchor_v2` 和 `layout_uid_v1`
- 还需要同步放宽 `segment_index / segment_total` 的过滤
  - `layout_uid_v1` 的整表锚点常见是 `segment_index=1, segment_total=1`
  - 旧逻辑会把所有 `segment_index > 0` 的锚点都判为不可跳
  - 结果是：
    - `...` 菜单里的“证据”消失
    - hover 证据预览也一起失效
  - 当前改成：
    - `anchor_v2` 仍保守过滤 segment anchors
    - `layout_uid_v1` 允许 `1/1` 这类 layout-level anchors 正常参与跳转与 hover

## 当前边界

这轮没有完成复杂表格的最终重构。

仍保留的后续项：

- `rowspan / colspan` 更完整的 fidelity
- 表格 note / footnote 的更强语义物化
- OCR 不稳定公式的更激进清洗规则

## 2026-03-12 23:48 新一轮表格重构目标

当前 `paper 85 / page 7` 的原始 DocMind truth 已再次核对：

- `type = table`
- `numRow = 20`
- `numCol = 6`
- `cells = 106`
- `merge_cells = 1`

这说明：

- DocMind 足以支持高质量结构恢复
- 当前问题不在 truth 不足，而在 `/read` 的 table materialization 仍然过于简化

本轮收敛方向调整为：

1. `semantic table first`
   - 直接以 `table_cells` 的 `row_start/row_end/col_start/col_end` 作为真值
   - 生成 canonical grid，再渲染成语义 `<table>`
2. `geometry-informed widths`
   - 保留 cell 几何，按原始 x 坐标推列宽
   - 不再只靠文本长度和平均列宽
3. `caption / notes` 语义分层
   - caption 单独保留，不塞进顶部 card title
   - note / footnote 单独保留，不混入表体
4. `image fallback second`
   - 对 merge/cell 结构明显异常的表，允许降级成原图展示
   - 但不影响整表 evidence 主链

本轮不做：

- 继续扩展 cell/row 级 evidence 交互
- 修改全局 evidence preview 主链
- 用 AI 或 markdown 文本继续猜表格结构

## 2026-03-12 23:58 本轮实现

本轮已落下的结构改动：

1. 后端 `TablePanel` props 增加 `column_widths`
   - 直接基于 DocMind `table_cells` 的几何范围计算
   - 不再让前端纯按平均列宽或文本长度猜列宽
2. `table_cells` 继续保留 cell 级 bbox
   - `x0/x1/y0/y1`
   - polygon 存在时可从 polygon 反推 bbox
3. 前端表格渲染改成更接近语义表的执行方式
   - 使用 `<colgroup>` 应用列宽
   - 第一列在合适时作为 row header 样式处理
   - 数值列使用更稳定的 tabular 数字样式
   - 单元格 padding 和行高收紧，减少 spreadsheet 感
4. 多行 header 收敛成单语义表头行
   - DocMind 的前两行 header 仍然保留在 truth 中
   - `/read` 渲染时不再把它们画成两行独立 `<thead><tr>`
   - 而是按列合并成一个表头单元，单元内部做两行文本展示
5. continuation rows 收敛成 logical rows
   - 对首列缺失、仅补充后续列值的 body row，不再单独渲染成新行
   - 而是并回上一条 logical row，在同列内按换行展示
   - 这条规则只影响 `/read` 表格展示层，不改 DocMind truth 和 evidence chain
6. sparse rows 保留原列偏移
   - 对物理行里缺失前置列的情况，不允许直接把现有单元格从第 0 列开始左对齐渲染
   - 必须按 `col_start / colspan` 补齐空占位，保留原始列偏移
   - 否则会出现“行数增加”和“数值整体左漂/错列”的问题

## 2026-03-13 00:12 续行/稀疏行收敛

这一轮继续收 `TablePanel` 的前端显示语义，不改后端 DocMind truth：

1. `continuation rows -> logical rows`
   - 不能只凭“首列缺失”就并回上一逻辑行
   - 只有前一逻辑行里存在 `rowEnd` 覆盖到当前物理行、且覆盖了前置列的 cell 时，才允许并回
   - 也就是续行判断必须以 DocMind `cells[].yec/xsc/xec` 真值为约束，而不是只靠稀疏文本模式
2. `sparse rows keep placeholders`
   - 表格行渲染时不再只遍历当前行已有 cell
   - 而是按 `col_start / colspan` 生成完整 row slots
   - 对缺失列补空占位 `<td>`，防止后续列整体左漂

这一层只影响 `/read` 的 table presentation，不动：

- `table_cells`
- `source_layout_ids`
- evidence preview 主链
- DocMind `cells[]` 原始真值

## 2026-03-12 17:50 no-drop 回退节点补充

这轮又暴露出一条独立问题：

- `layout_uid_v1` 的正文节点如果经过 `no_drop` 自动回退注入
- 节点文本还在
- 但节点只有 `source_block_ids`
- 没有 `source_atom_ids`
- 也没有 `layout_uid_v1` anchor

结果就是：

- `...` 菜单里只剩 `复制 / 拖拽`
- hover 不再触发证据预览
- 用户会误以为“同步没进容器”或“证据功能又坏了”

本轮收口方式：

- `no_drop` 回退节点优先从 `page_grounding_v1 + layout_unique_id` 重建 `layout_uid_v1` anchor
- 同时把 `source_atom_ids/source_layout_ids` 一并补回节点
- 只有在 grounding 不可用时才退回旧的 `anchor_v2/source_anchor`

这样做的意义是：

- 回退节点不再是“有文本没证据”的孤岛
- `layout_uid_v1` 证据链对正文节点和表格节点保持一致
- 前端 `ActionBar` 不需要再猜“这是不是旧式 block anchor”

## 2026-03-12 18:05 全局证据 gate 回归修复

后续又确认了一条更上游的全局回归：

- `/read` 主页面在 `PaperReaderPage.tsx` 里还有一套旧的 `isActionableAnchor`
- 这套逻辑只接受 `coord_version = anchor_v2`
- 所有新生成页的 `layout_uid_v1` anchor 都会被主页面层提前判死

影响范围不是单一表格页，而是：

- 任何新生成的 `/read` 页面
- hover 证据预览
- `...` 菜单里的 `证据`
- 右栏 pinned evidence

本轮修复：

- `PaperReaderPage.tsx` 的主页面级 `isActionableAnchor` 现在和 reader 组件层保持一致
- `layout_uid_v1` anchor 只要满足：
  - `source_layout_id` 存在，或
  - `geometry.polygons` 存在
  就允许进入证据链
- `anchor_v2` 仍然保持 `canonical_block_id` 校验，不放宽旧链路约束

这一步的作用是把 `/read` 的“全局证据入口”重新对齐到 `layout_uid_v1`，不再只有局部组件层修了、主页面层还在拦。
