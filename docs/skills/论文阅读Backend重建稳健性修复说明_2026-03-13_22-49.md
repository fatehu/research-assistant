# 论文阅读 Backend 重建稳健性修复说明

时间：2026-03-13 22:49

## 背景

在本地 backend-only 正式重建时，CUDA torch wheel 已经确认走到：

- `https://download.pytorch.org/whl/cu121`

但构建仍可能失败在下载阶段，表现为：

- `torch` wheel 下载长时间停滞
- 最终触发 hash mismatch

这类失败不说明配置错误，而更像是：

- 网络传输中断
- 下载内容不完整
- 构建过程中的临时传输异常

## 目标

增强 Dockerfile 中 torch 安装步骤的稳健性：

- 失败时自动重试
- 不改变本地 `cu121` / CI `cpu` 分流
- 不改变 backend 作为唯一 build owner 的设计

## 方案

在 [backend/Dockerfile](/mnt/d/codefield/agent-platform/research-assistant/backend/Dockerfile) 中：

1. 保留现有 `ARG TORCH_INDEX_URL`
2. 增加 `ARG TORCH_PACKAGE=torch`
3. 将单次 `pip install torch` 改为有限次重试循环
4. 每次失败后打印提示并 sleep，再继续下一轮
5. 最终仍失败时显式退出 1

## 不做的事

- 不回退到 CPU torch
- 不改 CI override
- 不改 frontend / postgres / redis
- 不改变 runtime GPU 配置

## 回退

如果该重试逻辑引发不可预期问题，可直接回退到当前单次安装实现：

- 删除 `TORCH_PACKAGE`
- 删除循环
- 恢复单条 `pip install --index-url ${TORCH_INDEX_URL}`
