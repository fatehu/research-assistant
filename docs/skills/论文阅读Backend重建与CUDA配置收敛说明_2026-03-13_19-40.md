# 论文阅读 Backend 重建与 CUDA 配置收敛说明

时间：2026-03-13 19:40

## 背景

当前 backend 重建成本异常高，且本地 Docker backend 实际没有按 NVIDIA GPU 路径构建。

已确认的根因：

1. `backend/.dockerignore` 基本为空
   - 仅有 `models/`
   - 本地 `backend/.venv-*`、`uploads/`、`docs/tests/artifacts/` 等大目录会进入 build context

2. 仓库位于 `/mnt/d/...`
   - WSL 下文件系统类型是 `9p`
   - Docker 传输 build context 特别慢

3. Docker backend 虽然 runtime 配了 GPU
   - `docker-compose.yml` 里已有 `gpus: all`
   - 但 `.env` 里 `TORCH_INDEX_URL` 仍指向 CPU wheel

4. `backend/docker-entrypoint.sh` 之前被写成 CRLF
   - 这会导致镜像里的 shebang 失效
   - backend 重启后直接起不来

## 目标

本轮不动业务逻辑，只收敛 backend rebuild 基线：

1. backend build context 显著瘦身
2. 本地默认切到 CUDA torch wheel
3. shell entrypoint 不再因为 CRLF 污染镜像
4. 为后续真正需要的 backend rebuild 降低成本和失败率

## 实施范围

### 1. build context 瘦身

收敛 `backend/.dockerignore`，至少排除：

- `.venv*`
- `__pycache__`
- `.pytest_cache`
- `uploads`
- `docs/tests/artifacts`
- `tests`
- 其他明显只用于本地开发/缓存的目录

原则：

- 不排除 backend runtime 必需代码
- 不排除 `app/`、`alembic/`、`requirements.txt`、`docker-entrypoint.sh`

### 2. CUDA 构建默认值

将本地 docker backend 的 torch wheel 来源收敛到 CUDA 版本：

- `.env`
- `.env.example`

目标值：

- `TORCH_INDEX_URL=https://download.pytorch.org/whl/cu121`

说明：

- `docker-compose.yml` 已支持通过 `TORCH_INDEX_URL` 传入 build arg
- 本轮不改 compose 里的 fallback 默认值，避免影响非 NVIDIA 环境
- 真正启用 CUDA 以 `.env` 为准

### 3. 行尾约束

增加 git 行尾约束，防止 shell 脚本再次变成 CRLF：

- `backend/docker-entrypoint.sh`
- 视情况可扩到 `*.sh`

## 非目标

本轮不做：

- backend 业务逻辑修改
- `/read` 或 `/experience` 功能迭代
- Docker 镜像体积的全面优化
- CI 流水线镜像策略重构

## 风险

1. `.dockerignore` 排除过多会导致镜像缺文件
   - 需要保持 backend runtime 必需路径完整

2. CUDA wheel 只适用于本地 NVIDIA 环境
   - 非 NVIDIA 环境仍应显式覆盖回 CPU

3. 当前工作树很脏
   - 本轮只动极少数 infra/config 文件
   - 避免把无关业务改动混进来

## 回退方式

如果这轮引发 backend 构建异常：

1. 回退本次 infra/config 提交
2. 恢复原 `.dockerignore`
3. 将 `.env` / `.env.example` 的 `TORCH_INDEX_URL` 改回 CPU
4. 保留本说明文档，后续再按更小范围重试
