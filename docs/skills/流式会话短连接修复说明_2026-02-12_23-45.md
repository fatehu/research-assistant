# 流式会话短连接修复说明（2026-02-12 23:45）

## 1. 问题背景
在流式对话（SSE）场景下，`ToolRegistry` 之前直接持有请求级 `AsyncSession`，导致数据库会话跟随整段流式生命周期。
当单次对话持续时间长、并发上升时，连接池会被长时间占用，放大超时和抖动风险。

## 2. 本次修复目标
将知识库检索工具改为“按次调用短会话”模式，避免会话在整个流式响应期间常驻。

## 3. 技术方案
1. `KnowledgeSearchTool` 支持两种模式：
- 直接会话模式：已有 `db` 时复用；
- 短会话模式：仅传 `db_session_factory`，每次执行 `knowledge_search` 时 `async with` 新会话。

2. `ToolRegistry` 支持注入 `db_session_factory`：
- 注册 `knowledge_search` 的条件从“有 db”扩展为“有 db 或有 db_session_factory”。

3. 流式入口改造：
- `chat`、`codelab`、`notebook_agent` 的流式工具链都改为传 `db_session_factory`，不再把请求级 `db` 长驻给工具层。

## 4. 具体改动
1. `backend/app/services/agent_tools.py`
- `KnowledgeSearchTool.__init__` 增加 `db_session_factory`。
- `execute` 增加短会话分支。
- 提取 `_execute_with_db`，统一核心检索逻辑。
- `_get_shared_kb_ids` 改为显式传入 `db`。
- `ToolRegistry` 增加 `db_session_factory`，并按“db 或 factory”注册知识搜索工具。
- `get_tool_registry` 增加 `db_session_factory` 参数。

2. `backend/app/api/chat.py`
- 去掉 `async with async_session_factory() as tool_db` 的整段长会话。
- 改为 `get_tool_registry(db=None, db_session_factory=async_session_factory, ...)`。

3. `backend/app/api/codelab.py`
- 创建 `ToolRegistry` 时改为 `db=None + db_session_factory=async_session_factory`。

4. `backend/app/api/notebook_agent.py`
- `NotebookToolRegistry` 构造函数支持 `db_session_factory`。
- 聊天和工具列表入口都改为 `db=None + db_session_factory=async_session_factory`。

## 5. 效果
1. 流式链路中不再持有单个长生命周期工具会话。  
2. `knowledge_search` 在每次调用时获取并释放短会话，降低连接池长期占用风险。  
3. 不改变检索功能行为，仅改变会话生命周期策略。
