# 检索性能优化阶段2_中文FTS分词_2026-02-13_11-39

## 1. 本次目标
实现中文全文检索可用化：在不引入 PostgreSQL 分词扩展的前提下，通过应用层分词让 hybrid retrieval 在中文语料上有效召回。

## 2. 使用技术
- 应用层中文分词：`jieba`
- 数据模型增强：`document_chunks.content_segmented`
- PostgreSQL FTS：`to_tsvector('simple', coalesce(...))` + GIN 表达式索引
- 渐进回填脚本：批处理、可限流、可 dry-run

## 3. 关键改动
- `backend/app/models/knowledge.py`
  - `DocumentChunk` 新增 `content_segmented` 字段。
- `backend/alembic/versions/010_add_content_segmented_and_fts_index.py`
  - 新增列 `content_segmented`
  - 新增索引 `ix_chunks_content_segmented_fts`（GIN, expression index）
- `backend/app/services/chinese_segmentation_service.py`
  - 新增 `segment_text_for_fts()`：
    - 中文文本使用 `jieba` 分词并空格拼接
    - 非中文文本保留 token 化结果
    - `jieba` 不可用时降级为原文，保证链路可用
- `backend/app/api/knowledge.py`
  - 入库时写入 `content_segmented`
  - 文本检索改为优先 `COALESCE(NULLIF(content_segmented,''), content)`
  - 查询词先走 `segment_text_for_fts(query)`
- `backend/app/services/agent_tools.py`
  - 与 API 同步：全文检索链路改为优先 `content_segmented`
  - 查询词同样先分词
- `backend/app/maintenance/backfill_content_segmented.py`
  - 回填脚本迁移至可跟踪目录，支持 `--batch-size/--limit/--dry-run`
- `backend/requirements.txt`
  - 增加 `jieba==0.42.1`

## 4. 达成效果
- 中文 query 的全文检索不再依赖空格分词，召回能力显著改善。
- 英文/数字 query 仍可通过通用 token 化路径检索，不破坏原有行为。
- 历史数据可通过回填脚本渐进升级，不阻塞线上请求。

## 5. 怎么使用
- 新文档入库自动生成 `content_segmented`
- 历史数据回填：
  - `python -m app.maintenance.backfill_content_segmented --dry-run --limit 1000`
  - `python -m app.maintenance.backfill_content_segmented --batch-size 200`

## 6. 风险与边界
- `jieba` 词典质量会影响某些领域术语切词效果，可后续增补用户词典。
- 回填脚本依赖数据库可达，建议在低峰执行并观察批次耗时。
