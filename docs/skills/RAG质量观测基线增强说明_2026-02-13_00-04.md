# RAG质量观测基线增强说明（2026-02-13 00:04）

## 1. 本次更新解决的问题
当前系统已经有 Query Rewrite / Hybrid / Reranker / Contextual Compression / 引用校验，但缺少统一的运行期质量指标输出。
这会导致两类问题：
1. 很难在真实流式会话中快速判断“这轮 RAG 是否真的用了知识检索、引用是否合规”。
2. 缺少可回归的质量基线，后续改动时不易做对比评估。

## 2. 更新目标
1. 为 ReAct RAG 流水线增加统一 `rag_metrics` 输出，落在 `done` 事件中。
2. 将 `rag_metrics` 透传到三条流式链路：AI 对话、CodeLab Agent、Notebook Agent。
3. 增加可自动化回归的“最小 E2E 基线测试”，验证检索后引用有效性与指标正确性。

## 3. 使用的技术
1. ReAct Agent 上下文状态扩展（`AgentContext` 计数字段）。
2. 运行后质量聚合（`_build_rag_metrics`）。
3. 流式事件透传（SSE done payload 扩展）。
4. pytest 脚本化回合测试（Mock LLM + Mock Tool 的两轮 ReAct 流程）。

## 4. 具体怎么做的
1. `backend/app/services/react_agent.py`
- 在 `AgentContext` 增加统计字段：
  - `knowledge_search_calls`
  - `compression_calls`
  - `compression_success_chunks`
  - `compression_fallback_chunks`
  - `citation_repair_attempts`
  - `citation_repair_successes`
- 新增 `_build_rag_metrics(context)`，统一产出：
  - 知识检索调用次数
  - 来源标签数量/列表
  - 答案引用数量
  - 是否要求引用
  - 引用是否合法
  - 引用修复次数与成功次数
  - 压缩调用与命中/回退块数
- 在所有 `knowledge_search` 路径（流式主路径、异常兜底路径、非流式路径）统一累计计数。
- `run()` 的 `done` 事件新增 `rag_metrics` 字段。

2. `backend/app/api/chat.py`
- 接收 Agent done 中的 `rag_metrics`，并透传到 SSE `event=done` 载荷。

3. `backend/app/api/codelab.py`
- 接收 Agent done 中的 `rag_metrics`，并透传到 SSE `type=done` 载荷。

4. `backend/app/api/notebook_agent.py`
- 增加对 Agent `done` 事件处理，提取并透传 `rag_metrics` 到最终 `type=done`。

## 5. 怎么用
1. 正常走流式问答（Chat/CodeLab/Notebook Agent）即可。
2. 在前端或调试工具读取最后一个 `done` 事件中的 `rag_metrics`。
3. 可直接用以下字段做质量判断：
- `knowledge_search_calls` 是否大于 0
- `source_labels_count` 是否大于 0
- `citation_required` 与 `citation_valid` 是否匹配
- `compression_success_chunks` / `compression_fallback_chunks` 比例

## 6. 做到了什么
1. RAG 质量从“日志人工判断”升级到“结构化指标输出”。
2. 三套 Agent 流式链路观测口径统一，可做横向比较。
3. 为第 7 项后续扩展（在线看板、A/B 对比、阈值调优）建立了稳定接口。

## 7. 怎么感知效果
1. 同一条知识问答完成后，可直接从 done 事件确认：
- 本轮是否使用过知识检索；
- 最终答案引用是否合规；
- 压缩是否命中还是主要走回退。
2. 回归测试可稳定断言 `rag_metrics` 结构与关键数值，不再只看自然语言输出。
