# 全量整改阶段03：Knowledge 事务边界与错误语义统一实施说明

- 时间：2026-02-23 10:44
- 阶段目标：收敛 `knowledge.py` 的事务失败路径和文件清理逻辑，统一关键错误响应结构。
- 关联 commit：`fix(knowledge): 统一事务边界与错误语义`

## 本阶段改动
1. 在 `backend/app/api/knowledge.py` 新增 `_build_error_detail`，将关键失败场景统一为 `code/message/details/request_id` 结构。
2. 新增 `_safe_remove_file`，替代原有裸 `except` 文件删除分支，统一日志与容错行为。
3. 在上传文档流程中强化事务边界：
   - 文件写入异常只捕获 `OSError` 并返回结构化错误。
   - 文档记录 `commit` 失败时执行 `rollback` + 文件清理，避免“库里无记录但磁盘残留文件”。
4. 将删除知识库/删除文档中的裸 `except` 删除并改为统一安全删除函数。

## 设计取舍
1. 优先收敛高价值失败路径（上传/删除）而非一次性重写全文件，避免大面积回归风险。
2. 数据库提交异常收敛到 `SQLAlchemyError`，避免再次引入宽异常计数膨胀。

## 风险与回滚
1. 风险：低。主要是失败路径增强，不改变成功主路径行为。
2. 回滚：直接回滚本 commit 即可恢复原行为。

## 效果感知
1. 上传失败和写库失败均可返回结构化错误体，便于前端与日志定位。
2. 文件系统残留风险降低，删除路径更可观测。
