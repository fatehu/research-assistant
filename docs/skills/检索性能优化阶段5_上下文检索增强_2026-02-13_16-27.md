# 检索性能优化阶段5：上下文检索增强

- 记录时间：2026-02-13 16:27
- 阶段目标：落地 Chunk 上下文增强与相邻窗口检索，完成可回放的回填/重建维护链路。

## 本次使用的技术
- 数据迁移：Alembic 新增 `context_summary` 字段迁移（011）。
- 检索增强：新增 `contextual_retrieval_service`，统一封装 `context_summary` 构造、embedding 输入拼装、相邻窗口归一化与合并。
- 入库链路增强：文档处理时为 chunk 写入 `context_summary`，并将 paragraph 级 embedding 输入改为 `context_summary + content`。
- 查询增强：搜索接口与 Agent Tool 支持 `include_adjacent_chunks` / `adjacent_window`，返回 `metadata.adjacent_context`。
- 运维脚本：新增 `backfill_context_summary_and_embeddings`，支持 `backfill/rebuild`、`dry-run`、批次、limit、start-doc-id；并新增前置列校验与失败判定。
- 迁移稳健性修复：将 010/011 revision id 缩短到 Alembic 默认长度限制内，并将 DDL 改为幂等（IF EXISTS/IF NOT EXISTS）。

## 目的是什么
- 提升检索结果的语义完整性与上下文连续性。
- 为“命中 chunk + 邻近语境”提供统一可控的数据结构。
- 让回填/重建脚本具备可预检、可复跑、可观测的工程属性。

## 怎么用
1. 执行迁移：`alembic upgrade head`。
2. 搜索接口按需传参：
   - `include_adjacent_chunks=true`
   - `adjacent_window=1~3`
3. 维护脚本：
   - 回填：`python -m app.maintenance.backfill_context_summary_and_embeddings --mode backfill --batch-size 200`
   - 重建（演练）：`python -m app.maintenance.backfill_context_summary_and_embeddings --mode rebuild --dry-run`

## 做到了什么
- `DocumentChunk` 已新增 `context_summary` 字段并进入迁移链。
- API 与 Tool 双链路均可返回 `adjacent_context`。
- paragraph 级 embedding 输入已包含结构化上下文。
- 脚本在执行前会检查必要列，避免“truncate 后才发现 schema 不匹配”。
- 重建流程不再仅凭函数返回判断成功，而是按文档最终状态判定失败。

## 怎么感知效果
- 检索返回结果中 `metadata.adjacent_context` 可直接观察上下文补全。
- 命中 chunk 首尾边界不越界，窗口大小可控（1-3）。
- 回填/重建日志包含 processed/failed/recount，可定位批次进度与失败原因。

## 备注
- 生产默认向量主线仍为 1024 维；本阶段不切维度，只增强上下文检索质量。
