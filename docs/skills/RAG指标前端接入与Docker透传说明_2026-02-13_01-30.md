# RAG指标前端接入与Docker透传说明（2026-02-13 01:30）

## 1. 本次更新要解决的问题
后端 `done` 事件已经输出 `rag_metrics`，但前端未消费，导致运行时无法在界面直接观察 RAG 质量（检索调用次数、引用有效性、压缩命中情况等）。
同时 Docker 前端服务缺少 `VITE_SHOW_RAG_METRICS` 透传，导致开关在容器化部署中不可控。

## 2. 本次使用的技术
1. TypeScript 类型扩展：新增 `RagMetrics` / `MessageMetadata`。
2. SSE done 事件接线：在 Chat 与 Notebook Agent 消费并保存 `rag_metrics`。
3. 前端条件渲染：通过 `SHOW_RAG_METRICS` 控制可折叠质量面板显示。
4. Docker Compose 环境变量透传：前端容器注入 `VITE_SHOW_RAG_METRICS`。

## 3. 具体怎么做
### 3.1 API 与类型
文件：`frontend/src/services/api.ts`
1. 新增 `RagMetrics` 类型。
2. 新增 `MessageMetadata`，并将 `Message.metadata` 收敛为可包含 `rag_metrics` 的结构。
3. 为 `AgentChatEvent` 增加 `rag_metrics?: RagMetrics`。
4. 导出 `SHOW_RAG_METRICS` 常量，统一读取前端开关。

### 3.2 Chat SSE 接线
文件：`frontend/src/stores/chatStore.ts`
1. 在 `done` 事件分支解析 `doneData.rag_metrics`。
2. 将结果写入助手消息 `metadata.rag_metrics`。

### 3.3 聊天页展示
文件：`frontend/src/pages/chat/components/MessageBubble.tsx`
1. 新增 `parseRagMetrics` 解析函数。
2. 在非流式 AI 消息中新增可折叠 `RAG质量` 面板。
3. 展示关键指标：
- `knowledge_search_calls`
- `source_labels_count`
- `answer_citation_count`
- `citation_valid`
- `compression_success_chunks/compression_fallback_chunks`
4. 面板受 `SHOW_RAG_METRICS` 开关控制。

### 3.4 Notebook Agent 展示
文件：`frontend/src/components/NotebookAgentPanel.tsx`
1. 在 `done` 事件中保存 `event.rag_metrics` 到消息 `metadata`。
2. 在助手消息区增加可折叠 `RAG质量` 面板。
3. 同样受 `SHOW_RAG_METRICS` 开关控制。

### 3.5 Docker 透传
文件：`docker-compose.yml`
1. `frontend.environment` 新增：
- `VITE_SHOW_RAG_METRICS=${VITE_SHOW_RAG_METRICS:-false}`

文件：`.env.example`
1. 新增示例项：
- `VITE_SHOW_RAG_METRICS=false`

## 4. 做到了什么
1. 后端 `done.rag_metrics` 到前端 UI 的链路已打通。
2. Chat 与 Notebook Agent 均可显示统一口径的 RAG 质量指标。
3. Docker 环境可通过 `.env` 一键控制指标面板开关。
4. 不影响默认用户体验（开关可关闭）。

## 5. 怎么感知效果
1. 开启 `VITE_SHOW_RAG_METRICS=true` 后，AI 回答卡片会出现 `RAG质量` 折叠面板。
2. 同一轮完成事件中可观察检索次数、引用有效性与压缩命中/回退。
3. 关闭开关后，面板不显示，业务不受影响。
