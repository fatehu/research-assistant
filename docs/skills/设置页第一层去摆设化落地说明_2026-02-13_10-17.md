# 设置页第一层去摆设化落地说明_2026-02-13 10:17

## 1. 本次目标
将设置页中“看起来可用但未闭环”的第一层能力落地：
- 修复修改密码链路（前端调用与后端接口一致）
- 让通知类开关变为“可保存、可回显”的真实配置（基于用户 `preferences`）

## 2. 使用的技术
- FastAPI + Pydantic
  - 新增密码修改请求模型，使用 JSON body 接收参数，避免 query 传密码。
- React + TypeScript + Ant Design
  - 将 `Switch defaultChecked` 改为受控组件（`checked + onChange`）。
  - 增加保存通知偏好的提交动作，并更新前端用户态。
- Zustand 用户态更新
  - 保存后调用 `updateUser`，确保页面刷新前后状态一致。

## 3. 怎么做的
### 3.1 后端
- 文件：`backend/app/schemas/user.py`
  - 新增 `UserPasswordChange` 模型：`old_password`、`new_password`。
- 文件：`backend/app/api/users.py`
  - `PUT /api/users/password` 改为接收 `UserPasswordChange` JSON body。
  - 增加“新旧密码不能相同”的校验。

### 3.2 前端
- 文件：`frontend/src/pages/user/SettingsPage.tsx`
  - 修改密码调用从 `POST /api/auth/change-password` 调整为 `PUT /api/users/password`。
  - 新增通知偏好状态 `notificationPreferences`，初始值从 `user.preferences.notifications` 回填。
  - 登录通知、邀请通知、公告通知、系统通知四个开关改为受控。
  - 新增“保存通知偏好”按钮，保存到 `PUT /api/users/profile` 的 `preferences.notifications`。

## 4. 做到了什么
- 设置页“修改密码”不再是无效按钮，接口链路可达。
- 通知开关不再是纯 UI，能真实写回后端并在用户态中回显。
- 完成“第一层去摆设化”：可配置 + 可保存 + 可感知。

## 5. 如何感知效果
- 在设置页切换通知开关并点击“保存通知偏好”，有成功提示。
- 刷新页面后，开关状态保持不丢失（来自 `preferences.notifications`）。
- 修改密码提交后，返回成功/失败提示，不再出现接口不存在。

## 6. 边界说明
- 本次仅实现“偏好存储层”，未实现邮件通道/推送通道。
- “登录通知”当前是用户偏好记录，不等同于已开通邮件告警。
