# RAG稳健性分阶段修复说明（2026-02-12 22:42）

## 1. 目标
本次按照“先阻断、再可信、再可控”的工程顺序，逐步修复当前 RAG 的关键短板，并采用多次提交保证每一步可回滚、可审计。

## 2. 分阶段改动

### 阶段一：修复阻断问题（Notebook Agent 异步初始化）
1. `backend/app/api/notebook_agent.py`
- 将 `llm_service = get_llm_service()` 修复为 `llm_service = await get_llm_service()`。
- 目的：避免把 coroutine 传入 ReActAgent 导致运行时属性访问异常。

2. `backend/tests/test_agent_db_wiring.py`
- 新增断言，验证 notebook agent 聊天路由源码中存在 `await get_llm_service()`。

### 阶段二：把“引用规范”升级为“程序校验”
1. `backend/app/services/react_agent.py`
- 在 `AgentContext` 新增 `allowed_source_labels`，记录本轮可用来源编号集合。
- 新增引用校验与修复逻辑：
  - `_extract_source_labels`
  - `_extract_answer_citations`
  - `_citations_are_valid`
  - `_ensure_citation_compliance`
- 在输出最终回答前统一执行校验，若引用缺失/越界，自动触发一次“来源修正”。
- 在 `knowledge_search` 工具观测结果写回时提取来源编号并加入上下文。

2. 压缩降级链路增强
- `react_agent._compress_knowledge_observation` 在压缩失败或无结果时，不再直接丢回原始输出，而是构造带 `[来源X]` 的回退内容。
- 目的：保证降级路径也有可引用来源。

3. 测试补充
- `backend/tests/test_react_agent_citation_policy.py` 增加：
  - 来源提取与校验测试
  - 引用修复测试
  - 压缩降级仍带来源标注测试

### 阶段三：统一检索可控性（去硬编码 + 对齐默认值）
1. `backend/app/config.py`
- 新增 `agent_knowledge_score_threshold`（默认 `0.5`）。

2. `backend/app/services/agent_tools.py`
- `KnowledgeSearchTool` 向量检索阈值从硬编码 `0.5` 改为配置驱动：
  - `score_threshold -> distance_threshold = 1 - score_threshold`
  - SQL 使用参数 `:distance_threshold`

3. `docker-compose.yml` 与 `.env.example`
- 新增 `AGENT_KNOWLEDGE_SCORE_THRESHOLD` 环境变量透传与示例配置。

4. `frontend/src/services/api.ts`
- 将 `knowledgeApi.search` 的默认选项改为：
  - `useReranker = true`
  - `useHybrid = true`
  - `useQueryRewrite = true`
- 目的：减少调用方未传 options 时出现“静默退化”。

5. 测试补充
- `backend/tests/test_tool_registry_knowledge_search.py` 新增断言，校验 `KnowledgeSearchTool.execute` 使用配置化阈值与参数化 SQL。

2. ReAct 后处理校验（answer post-check）  
3. 降级路径可追溯设计（fallback with source labels）  
4. 配置驱动阈值管理（Pydantic Settings + env）  
5. pytest 回归测试与接线测试
