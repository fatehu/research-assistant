# 检索性能优化阶段1_压缩批处理_2026-02-13_11-09

## 1. 目标
将上下文压缩从“每个 chunk 一次 LLM 调用”升级为“批量压缩主链路”，并加入高分直通与提取式降级，降低延迟、成本和超时风险。

## 2. 使用技术
- FastAPI / Pydantic Settings
  - 新增压缩模式、批次大小、重试次数、跳过阈值等配置项。
- LLM 批处理提示词设计
  - 单次请求压缩多个检索片段，返回 source_id 映射结果。
- Extractive Fallback
  - 句子切分 + 关键词重叠评分，在 LLM 异常或低相关时兜底。
- ReAct Agent 与 Knowledge API 协同
  - API 与 Agent 均透传 reranker_score，支持高分片段直接使用。

## 3. 实施内容
- 文件：`backend/app/services/contextual_compression_service.py`
  - `CompressionInput` 增加 `reranker_score`。
  - 新增 `compress_chunks_batched(...)`，支持批次分片、重试、解析、回退。
  - 新增高分直通策略：`reranker_score >= CONTEXTUAL_COMPRESSION_SKIP_RERANK_THRESHOLD` 时不走压缩。
  - 新增提取式降级：在超时/解析失败/低相关场景生成可读摘要，不再粗暴截断 320 字符。
  - `compress_chunks(...)` 按 `CONTEXTUAL_COMPRESSION_MODE` 在 `batch/single` 间切换。
- 文件：`backend/app/api/knowledge.py`
  - 构建 `CompressionInput` 时透传 `reranker_score`。
- 文件：`backend/app/services/react_agent.py`
  - 观察结果压缩时透传 `reranker_score`。
- 文件：`backend/app/config.py`、`.env.example`
  - 新增阶段性配置项（compression/query rewrite/ef_search 扩展参数），为后续阶段预留。

## 4. 达成效果
- top_k=5 的常见检索压缩场景，理论上由 5 次 LLM 压缩请求降为 1 次（单批次）。
- reranker 高分结果可直接进入回答上下文，减少不必要压缩。
- LLM 超时或失败时仍返回结构化可读压缩内容，稳定性更高。

## 5. 如何感知
- 观察日志中批处理压缩请求次数明显下降。
- 在高 reranker 分数结果上可见 `skip_high_reranker` 标记。
- 故障场景下结果含 extractive 文本而非空内容/粗暴截断。

## 6. 使用方法
- 默认开启批处理：`CONTEXTUAL_COMPRESSION_MODE=batch`
- 关键参数：
  - `CONTEXTUAL_COMPRESSION_BATCH_MAX_CHUNKS`
  - `CONTEXTUAL_COMPRESSION_BATCH_RETRY_ATTEMPTS`
  - `CONTEXTUAL_COMPRESSION_SKIP_RERANK_THRESHOLD`
- 如需回退旧行为可设为：`CONTEXTUAL_COMPRESSION_MODE=single`
