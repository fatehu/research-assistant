# 检索性能优化阶段3_改写缓存与跳过_2026-02-13_11-44

## 1. 本次目标
为 Query Rewrite 增加“自动跳过 + 进程内缓存”，减少无意义 LLM 调用，降低延迟和 token 成本，同时保持旧参数兼容。

## 2. 使用技术
- `rewrite_mode` 模式控制（auto/force/off）
- 规则跳过（短查询、关键词型查询）
- LRU + TTL 进程内缓存（`OrderedDict`）
- 返回结构增强：`cache_hit / skip_reason / llm_called`

## 3. 关键改动
- `backend/app/services/query_rewrite_service.py`
  - 重构 rewrite 流程，新增：
    - `should_skip_rewrite()`
    - `_cache_get/_cache_set`（受 `QUERY_REWRITE_CACHE_SIZE`、`QUERY_REWRITE_CACHE_TTL_SECONDS` 控制）
    - `rewrite_mode` 优先级处理（高于 legacy `use_query_rewrite`）
  - `QueryRewriteResult` 新增字段：
    - `cache_hit`
    - `skip_reason`
    - `llm_called`
- `backend/app/schemas/knowledge.py`
  - `SearchRequest` 新增 `rewrite_mode: Literal["auto","force","off"] = "auto"`
- `backend/app/api/knowledge.py`
  - 调用改写时透传 `rewrite_mode`
  - 检索结果 metadata 新增：
    - `query_rewrite_cache_hit`
    - `query_rewrite_skip_reason`
    - `query_rewrite_llm_called`
- `backend/app/services/agent_tools.py`
  - Tool 侧改写调用显式走 `rewrite_mode="auto"`
  - 返回结果数据补充改写观测字段

## 4. 达成效果
- 短查询、关键词型查询可以直接跳过改写，减少延迟。
- 重复查询命中缓存后不再重复调用 LLM。
- 兼容老参数：旧逻辑可继续使用，`rewrite_mode` 可覆盖旧行为。

## 5. 如何使用
- 默认：`rewrite_mode=auto`（建议）
- 强制改写：`rewrite_mode=force`
- 关闭改写：`rewrite_mode=off`
- 关键配置：
  - `QUERY_REWRITE_CACHE_SIZE`
  - `QUERY_REWRITE_CACHE_TTL_SECONDS`
  - `QUERY_REWRITE_SKIP_SHORT_CHARS`

## 6. 风险与边界
- 进程内缓存是单实例缓存，多副本场景下命中率由流量分布决定。
- 自动跳过规则为启发式，后续可根据线上统计微调。
