# 论文阅读 `/read` 撤销全局 Raster 预览特判说明

## 结论

这次修复不再继续调整 `layout_uid_v1` 的全局 evidence preview 坐标系，而是**撤销之前错误引入的 DocMind raster 预览特判**，把 `/read` 的 hover / pinned evidence 统一恢复到表格修复前的 PDF.js 主链。

## 为什么要撤销

表格重构本来只应该影响：

- 表格分组
- 表格物化
- 表格自身的 evidence materialization

不应该影响：

- 所有 `/read` 节点的 hover preview
- 所有 `/read` 节点的 pinned evidence
- 全局 `ActionBar -> 证据` 的预览绘制基准

但后续引入的 `layout_uid_v1 -> renderAnchorEvidenceImageFromRaster(...)` 特判，实际上把全局 evidence preview 从 PDF.js 页面坐标切到了另一条单独的 raster 路径，导致了整体右下偏移。

## 这次改动

只做一件事：

- 删除 `PaperReaderPage.tsx` 中 `layout_uid_v1` 的 raster preview 特判
- 删除 `buildDocmindPageImageProxyUrl(...)`
- 删除 `loadRasterImage(...)`
- 删除 `renderAnchorEvidenceImageFromRaster(...)`
- `renderPreviewForAnchor(...)` 重新统一回：
  - `pdfDoc.getPage(targetPage)`
  - `pageProxy.getTextContent()`
  - `renderAnchorEvidenceImage(pageProxy, textItems, anchor)`

## 保留边界

这次不处理：

- 表格 fidelity
- rowspan / colspan
- row/cell 级高保真证据
- `/experience` 的任何逻辑

也不移除 backend 的 DocMind page-image proxy route；只是前端 `/read` 不再把它当成全局 preview 主链。

## 原则

后续如果继续处理表格：

1. 表格问题只在表格物化层解决
2. 不再改 `/read` 全局 evidence preview 主链
3. 任何新证据绘制实验，都不能绕开既有 PDF.js preview 基线
