# 检索增强技能说明（2026-02-12）

## 1. 本次使用的技术
- 向量检索：`pgvector`（PostgreSQL 内）
- 全文检索：PostgreSQL FTS（`to_tsvector`、`websearch_to_tsquery`、`ts_rank_cd`）
- 融合排序：RRF（Reciprocal Rank Fusion）
- 精排：Cross-Encoder Reranker（默认 `BAAI/bge-reranker-v2-m3`）
- 两阶段链路：`召回 -> 融合 -> 精排 -> 返回`

## 2. 目的是什么
- 提升 Top-N 结果排序质量，降低“召回到了但排不上来”的问题。
- 在不引入新基础设施的前提下实现混合检索，保持部署和运维简单。
- 兼容现有 RAG 流程，让 LLM 拿到更高质量上下文。

## 3. 怎么用（使用方式）

### 3.1 配置项
- 混合检索：
  - `ENABLE_HYBRID_RETRIEVAL=true`
  - `HYBRID_VECTOR_TOP_K=20`
  - `HYBRID_TEXT_TOP_K=20`
  - `HYBRID_RRF_K=60`
- 精排：
  - `ENABLE_RERANKER=true`
  - `RERANKER_MODEL=BAAI/bge-reranker-v2-m3`
  - `RERANKER_DEVICE=auto`
  - `RERANKER_TOP_K=20`

### 3.2 请求开关
- API 请求体支持：
  - `use_hybrid`：是否启用“向量 + 全文 + RRF”
  - `use_reranker`：是否启用 Cross-Encoder 精排

示例：
```json
{
  "query": "你的检索问题",
  "top_k": 5,
  "score_threshold": 0.05,
  "use_hybrid": true,
  "use_reranker": true
}
```

### 3.3 当前检索流程
1. 生成 query embedding  
2. 向量召回（pgvector）  
3. 全文召回（PostgreSQL FTS，可选）  
4. RRF 融合排序  
5. Reranker 精排（可选）  
6. 返回 top_k 给上层 Agent/LLM  

## 4. 做到了什么（交付结果）
- 检索链路升级为混合检索，并支持 RRF 融合。
- API 与 Agent 工具链路都已同步支持混合检索。
- 新增可观测元数据：`retrieval_mode`、`vector_rank`、`text_rank`、`rrf_score`、`reranker_score`。
- 支持降级：
  - FTS 异常时回退到向量检索；
  - Reranker 异常时回退到融合排序结果。

## 5. 怎么感知效果
- 离线指标：
  - `MRR@5`、`Recall@20`、`NDCG@5`
- 在线指标：
  - 命中率（top5 是否包含正确证据）
  - 回答可引用性（是否能在 chunk 中找到支撑）
  - 端到端延迟（重点关注 P95）
- 结果可解释性：
  - 观察返回 metadata 中 `retrieval_mode / rrf_score / reranker_score` 变化。
- A/B 对比建议：
  - A: `use_hybrid=false, use_reranker=false`
  - B: `use_hybrid=true, use_reranker=false`
  - C: `use_hybrid=true, use_reranker=true`
