## 背景

`/read` 的 `layout_uid_v1` 表格链路已经真实走到 `ai_logical_rows`，但 `paper 85 / page 6` 这类 benchmark 表仍然会把：

- 稀疏数值行
- 下一行的 `benchmark label + reported value + (±...)`

拆成两条逻辑行，导致页面里：

- `38.34`
- `(±2.52)`

被分开显示，而不是同一单元格内的上下两行。

## 已确认现象

当前 live payload 中：

- `engine_version = reader_compose_v11`
- `reconstruction_mode = ai_logical_rows`
- 但 `logical_rows` 仍包含：
  - 一条首列为空、只含多列数值的行
  - 紧随其后的一条含 benchmark label 和多列 `(±...)` 的行

进一步追查后确认：

- fresh rebuild 的 `logical_rows` 实际已经正确配对
- 真正错的是旧 `reader_compose_v11` 结果仍在页面里复用
- 因此除了保留 pairing normalization，还需要把 compose version 提升到 `reader_compose_v12`，强制新页面走最新物化结果

## 本次目标

只做表格逻辑行修复：

- 对 `logical_rows` 增加一层 deterministic pairing normalization
- 把 “value row + uncertainty row / sparse continuation row” 合并回同一逻辑行
- 不改：
  - `uniqueId`
  - `table_cells`
  - evidence/highlight 主链
  - `/experience`

## 规则方向

候选配对条件：

- 前一行：
  - 首列为空或缺失
  - 多列是 numeric-like
- 当前行：
  - 多列是 uncertainty-like，或带 benchmark label 且 uncertainty-like 占主导
- 两行在列上有足够重叠

合并方式：

- 相同列：
  - `value + "\n" + uncertainty`
- 前一行缺失而当前行有值的列：
  - 直接补入前一行
- `source_row_indices` 合并

## 回退边界

如果这轮效果不好，只回退：

- `logical_rows` pairing normalization
- 与其直接相关的 prompt 强化

不要回退：

- `reader_compose_v11` 页图本地化
- `ai_logical_rows` live 接入
- 全局 evidence preview 主链

## 当前落实

- fresh payload 已确认能产出：
  - `AIME 2024 -> 38.34\n(±2.52)`
  - `MATH 500 -> 89.85\n(±0.30)`
- compose version 已提升到 `reader_compose_v12`，用于切断旧 `reader_compose_v11` 缓存
