# 论文阅读 Generative UI：规划文案与展示文案分层说明

## 问题

`/experience` 页面里出现了多句明显像内部规划 note 的文案，例如：

- 把清洗后的正文作为主阅读流，避免让辅助卡片替代论文内容本身。
- 先围绕最关键的图或证据建立理解抓手，不急着把所有信息同时展开。

这些句子不是“内容解释错了”，而是**系统把内部 planning copy 直接暴露成了用户可见 summary**。

## 根因

当前 runtime 里有一层 `page_brief.storyboard`。它的 `purpose` 字段本意是：

- 告诉 planner / formatter 这一节的职责是什么
- 保留给 debug/workbench 看
- 辅助 section 排序和预算控制

但在 `build_experience_plan()` 里，这个 `purpose` 被直接写进了：

- `section.summary`
- `section.display_summary`

于是用户在产品页看到的不是“给读者的解释文案”，而是“给系统自己的规划语句”。

## 这轮设计决策

### 1. `storyboard.purpose` 继续保留，但只做内部 planning note

这部分不删除，因为它对：

- debug/workbench
- review
- 后续 formatter / telemetry

都有价值。

但它不再直接充当用户文案。

### 2. section summary 改为独立的用户展示文案

`build_experience_plan()` 现在会单独生成 reader-facing section summary，例如：

- focus stage:
  先看图或关键证据，抓住这页最重要的结果和比较对象
- reading flow:
  回到正文，确认作者如何解释这些结果，以及证据是否支撑结论

这层的目标是：

- 让用户读得懂
- 不暴露“系统在怎么想”
- 保留 generative UI 的解释层角色

### 3. planning note 改存到 `section.meta`

当前会保留：

- `planner_purpose`
- `planner_role`
- `planner_beat_id`

这样 debug/workbench 仍然能看见页面规划依据，但产品页主视图不会继续露出 planning 腔。

## 为什么这符合 generative UI 主线

这不是“润色几句文案”，而是继续收紧 contract：

- internal planning copy
- user-facing display copy
- raw evidence

这三层必须分开。

如果不分开，系统会不断把：

- storyboard purpose
- formatter rationale
- resource strategy

之类内部对象漏到页面上，最后看起来就像“提示词在说话”。

## 后续约束

- `storyboard.purpose` 不再直接映射到产品页 summary
- `/experience` 主视图优先消费 display copy
- internal planner text 只允许出现在 debug/workbench 或 details 中
