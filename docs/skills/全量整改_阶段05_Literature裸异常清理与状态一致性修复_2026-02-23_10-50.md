# 全量整改阶段05：Literature 裸异常清理与状态一致性修复实施说明

- 时间：2026-02-23 10:50
- 阶段目标：清理文献链路中的裸异常/宽异常点，并统一论文入库链接状态推导逻辑。
- 关联 commit：`fix(literature): 清理裸异常与长链路状态一致性`

## 本阶段改动
1. 在 `backend/app/api/literature.py`：
   - `_to_float` 中将字符串转浮点失败从 `except Exception` 收紧为 `except ValueError`。
   - 文献 Agent `paper_read` 路径的上下文写回失败改为捕获 `AttributeError/TypeError`，并记录 debug 日志。
2. 新增 `_derive_link_status_from_document`，统一按 `Document.status` 推导 `PaperKnowledgeLink.status/error_message/document_id`。
3. 在 `_run_document_processing_for_link` 与 `get_paper_knowledge_links` 两处复用同一状态推导函数，消除分叉逻辑：
   - `completed -> ready + error_message=None`
   - `failed -> failed + error_message`
   - `pending/processing -> processing + error_message=None`
4. 在 `backend/app/services/literature_service.py` 中将 arXiv 年份解析裸异常收紧为 `TypeError/ValueError`。
5. 补充 `backend/tests/test_literature_reader_api.py` 对状态推导函数的回归用例。

## 设计取舍
1. 先统一状态推导逻辑而非重写全链路，优先消除“同一状态不同分支表现不一致”的问题。
2. 保持现有接口与模型字段不变，确保前端兼容。

## 风险与回滚
1. 风险：低。主要影响异常路径与状态同步分支。
2. 回滚：可单 commit 回滚，不涉及数据库结构。

## 效果感知
1. link 状态写回一致性提高，`processing` 状态不会残留历史错误信息。
2. 异常分支可观测性增强，裸异常显著减少。
