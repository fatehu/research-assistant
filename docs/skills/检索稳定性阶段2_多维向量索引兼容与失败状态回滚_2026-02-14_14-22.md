# 检索稳定性阶段2：多维向量索引兼容与失败状态回滚
记录时间：2026-02-14 14:22

## 1. 本次更新用了哪些技术
- Alembic 迁移：新增 `014_drop_legacy_embedding_hnsw.py`。
- PostgreSQL/pgvector 索引治理：移除旧的全局 HNSW 索引，保留 256/512/1024 维表达式索引。
- FastAPI 异步事务恢复：在文档处理异常分支显式 `rollback` 后再写失败状态。
- Docker 在线升级验证：容器内执行 `alembic upgrade head` 并做 E2E 回归。

## 2. 目的是什么
- 修复“文档长期停留 processing，前端一直处理中”的真实线上体验问题。
- 确保自适应维度（256/512/1024）在同库共存时可正常入库。
- 保证后台任务失败后，状态可见且可恢复，不再出现“失败但界面显示处理中”。

## 3. 怎么做的
1. 复现问题：执行 `e2e/knowledge_upload_pipeline_e2e.ps1`，文档 600 秒内始终 `processing`。
2. 根因定位：
   - 后端日志报错 `different vector dimensions 256 and 1024`。
   - 旧索引 `ix_chunks_embedding_hnsw` 与多维向量共存冲突。
   - `process_document_task` 异常分支未先回滚事务，导致失败状态未落库。
3. 修复实现：
   - 新增迁移删除旧全局 HNSW 索引（`ix_chunks_embedding_hnsw` / `idx_chunks_embedding_hnsw`）。
   - `backend/app/api/knowledge.py` 异常分支改为：`logger.exception -> db.rollback -> 写 doc.failed`。
4. 发布动作：容器内执行 `alembic upgrade head`，并重启 backend。

## 4. 做到了什么
- 自适应维度 256 的 chunk 可正常写入数据库。
- 上传链路从“卡 processing”恢复为“可 completed/failed 终态”。
- E2E 上传-处理-检索链路在 Docker 环境跑通。

## 5. 怎么感知效果
- 前端文档列表不再长时间显示“处理中”且 `chunk=0`。
- 同一次 E2E 中可看到状态从 `processing` 进入 `completed`。
- 检索可返回结果，且日志显示 `dims=[256]`，说明弹性维度已被实际消费。

## 6. 怎么测试
- 前端质量校验：`npm run lint`、`npm run build`。
- 后端关键回归：
  `python -m pytest backend/tests/test_contextual_compression_service.py backend/tests/test_contextual_compression_batch_pipeline.py backend/tests/test_chinese_fts_segmented.py backend/tests/test_query_rewrite_service.py backend/tests/test_vector_search_tuning.py backend/tests/test_contextual_retrieval_window.py backend/tests/test_tool_registry_knowledge_search.py -q`
- E2E：`powershell -ExecutionPolicy Bypass -File e2e/knowledge_upload_pipeline_e2e.ps1 -BackendBaseUrl http://localhost:8888 -PollIntervalSeconds 3 -MaxWaitSeconds 600`

## 7. 结论
本阶段完成了“多维向量 + 文档状态可见性”的稳定性闭环：入库兼容、失败可回写、容器内端到端可验证。
