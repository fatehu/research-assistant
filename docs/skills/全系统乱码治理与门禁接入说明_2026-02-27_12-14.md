# 全系统乱码治理与门禁接入说明（主代码+文档）

## 目标
1. 在不改业务功能的前提下，建立统一的乱码检测能力。  
2. 将乱码检测纳入本地执行入口与 CI 门禁。  
3. 清理本轮命中的文档示例乱码词条，避免误导后续排查。  

## 本次改动
1. 新增检测脚本：`scripts/check_mojibake.py`  
   - 默认扫描：`backend/app`、`frontend/src`、`scripts`、`docs`。  
   - 默认排除：`backend/debug_scripts/**`、`**/node_modules/**`、`**/dist/**`、`**/.next/**`、`**/.playwright-cli/**`。  
   - 检测规则：  
     - UTF-8 解码错误。  
     - UTF-8 BOM。  
     - 高置信语义乱码词（如 `宸蹭粠`、`鏀惰棌`）。  
     - 乱码特征字符（如 `锟`、`�`、`銆`、`鈥`、`锛`）。  
   - 输出格式：  
     - 默认 `file:line:rule:snippet`。  
     - `--json` 输出结构化报告。  
   - 返回码：命中问题即返回非 0。  
2. 新增本地执行入口：  
   - `scripts/run_text_hygiene.ps1`（Windows）。  
   - `scripts/run_text_hygiene.sh`（Shell）。  
3. 新增单元测试：`tests/test_check_mojibake.py`。  
4. 更新 CI：  
   - `.github/workflows/pr-api-smoke.yml` 新增 `Mojibake guard`。  
   - `.github/workflows/nightly-e2e-full.yml` 新增 `Mojibake guard`。  
5. 更新规范文档：`scripts/code.md` 增加标准巡检命令。  
6. 清理文档示例：将旧的 `rg` 乱码词条示例替换为 `python scripts/check_mojibake.py --strict`。  

## 使用方式
1. 日常本地巡检：  
   - `python scripts/check_mojibake.py --strict`  
2. Windows 入口：  
   - `./scripts/run_text_hygiene.ps1 -Strict`  
3. 结构化报告：  
   - `python scripts/check_mojibake.py --strict --json`  

## 设计取舍
1. 本轮不处理 `backend/debug_scripts` 历史日志乱码。  
2. 词典 + 特征字符双规则并行，以减少漏报。  
3. 加入白名单关键词，避免把“乱码检测说明文字”误判为乱码。
