# 论文阅读模块：询问 Agent Core 与受限工具链落地说明（2026-02-16 05:08）

## 1. 本阶段目标
- 将论文询问主链路升级为 Agent Core 执行模式。
- 使用专用系统提示词约束主任务与引用规范。
- 强制工具白名单，仅保留：
  - `knowledge_search`（替换为论文范围受限版本）
  - `web_search`
  - `web_scrape`（若存在）
  - MCP 中与网页搜索/抓取相关的工具（按名称规则筛选）

## 2. 改动文件白名单
- `backend/app/api/literature.py`
- `backend/app/schemas/literature.py`
- `frontend/src/services/api.ts`
- `frontend/src/pages/literature/PaperReaderPage.tsx`

## 3. 后端关键实现
### 3.1 询问模式
- 为 `LiteratureAskRequest` 增加 `mode: agentic|classic`，默认 `agentic`。
- 缓存 key 增加 `mode` 维度，避免不同模式答案互相污染。

### 3.2 受限知识检索工具
- 新增 `LiteratureScopedKnowledgeSearchTool`（工具名仍为 `knowledge_search`）：
  - 仅检索当前请求允许的 `knowledge_base_id + document_ids`。
  - 返回结构化结果，并输出 `[来源X]` 可引用标记。

### 3.3 Agent Core 专用实现
- 新增 `LiteratureAskAgentCore`：
  - 使用论文询问专用系统提示词（先检索后回答、证据不足显式声明、引用规范）。
  - 通过 `allowed_tool_names` 固定 Function Calling 工具 schema。
- 新增工具注册构建函数：
  - 覆盖默认 `knowledge_search` 为范围受限版本。
  - 过滤工具到白名单。
  - 刷新 MCP 后再次过滤，防止越权工具进入。

### 3.4 结果与引用
- `agentic` 路径从 observation 中抽取 `knowledge_search` 结果作为 `sources`。
- 若 Agent 未拿到来源，回退到本地 RAG 检索补齐 `sources`。
- `sources` 统一透传 `idx/score_source` 等字段。

## 4. 前端联动
- 询问面板新增模式切换：
  - `Agentic（高质量）`
  - `Classic（快速）`
- 请求体新增 `mode` 字段。
- 回答引用解析已支持 `[来源X]` 与 `[X]` 两种格式并可点击跳转。

## 5. 风险与约束
- Agentic 模式质量更高但延迟波动更大（多轮工具调用）。
- MCP 可用性受环境配置影响，失败时会自动回退至本地可用工具。
- 仍保留 `classic` 路径，作为性能和稳定性兜底。
