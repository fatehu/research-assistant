# 论文阅读工作台V2：KeyTakeaways 邻页上下文概括

- 时间：2026-02-26 22:41
- 目标：将关键要点从“摘要截断拆句”升级为“LLM 基于上一页/当前页/下一页的上下文概括”。

## 本次改动
1. 在 composed 构建阶段新增邻页上下文聚合流程：
   - 读取 `page-1`、`page`、`page+1` 的结构化块。
   - 优先选取 `main_body` 的 heading/paragraph/list_item 作为候选证据块。
2. 新增 LLM 要点生成逻辑：
   - 模型自主决定要点数量（不固定条数）。
   - 输出严格 JSON（`items[].text`），不再要求证据 ID。
   - 自动清理省略号，避免 `...`/`…` 进入关键要点。
3. 更新 KeyTakeaways 渲染数据源：
   - 优先读取 `base_payload.takeaways`（AI 概括结果）。
   - 仅在 AI 失败时才回退到本地摘要拆句。
4. 暂时下线 KeyTakeaways 的“定位到证据”按钮：
   - 当前页面先聚焦可读概括，避免证据高亮质量不稳定造成误导。
5. 升级 compose 版本号：
   - `COMPOSE_ENGINE_VERSION` 升级为 `reader_compose_v3`。
   - 签名前缀升级为 `compose_v3`，避免旧缓存污染新逻辑。

## 影响范围
- `backend/app/services/literature_reader_compose_service.py`
- `backend/tests/test_literature_reader_composed.py`

## 预期效果
1. 关键要点条数不再固定为 3/8，而由模型按信息密度自主决定。
2. 要点不再是“截断长句 + 省略号”，而是更接近真正概括。
3. 当前页上下文不足时，可借助前后页信息减少语义断裂。
