# 论文阅读 `/read` 表格重构回归与证据链恢复说明

## 结论

这次证据回溯退化，不是 DocMind 真值不够，也不是 `layout_uid_v1` 设计本身有问题，而是**表格重构阶段把原本稳定的 whole-node evidence flow 绕开了**，同时运行态又继续复用了旧 engine/pipeline cache。

## 表格修复前 `/read` 的证据链

表格修复前，`TablePanel` 跟其他阅读节点一样，使用统一证据链：

1. 后端给节点写 `source_anchor_refs`
2. 节点整体包在 `withAnchorPreview(...)`
3. `ActionBar` 从 `source_anchor_refs` 自动推出 `jump_anchor -> 证据`
4. hover / 点击整张表，都走统一 evidence preview / pinned evidence 逻辑

这条链的优势是：

- 入口统一
- 不依赖表格特例逻辑
- 一张表就是一组 `uniqueId` bundle，对应一组 `blocks[].pos`

## 是什么破坏了它

### 1. 前端 `TablePanel` 被改成表格特例

在表格重构阶段，`frontend/src/pages/literature/readerComponents/index.tsx` 里的 `TablePanel` 增加了：

- `row_evidence`
- `cell_evidence`
- 顶部显式 `证据 / 预览` 按钮
- 行 hover / cell hover 的专用 evidence handler

结果是：

- 表格不再主要依赖统一 `withAnchorPreview + ActionBar`
- 一旦 row/cell evidence 不完整、缓存未刷新或 contract 半旧半新，整表级证据链就被绕开

### 2. 后端开始继续复用旧 cache

`build_or_get_composed_payload(...)` 原先仍允许：

- 复用旧 engine version 的 exact cache
- 复用不同 pipeline version 的 compatible cache

于是运行态会出现这种情况：

- 代码已修，但页面仍拿到 `reader_compose_v7` 的旧 payload
- 或者 `layout_uid_v1` 继续复用 `simplified_v2` 时代留下来的 compatible cache

## 这次恢复做了什么

1. 恢复表格 whole-node evidence flow
   - 表格重新回到统一 `ActionBar -> 证据`
   - 不再让 row/cell 特例覆盖整表证据链

2. 恢复整表 bundle 的 `source_layout_ids`
   - 不再只保留表体
   - caption/adjacent table bundle 回到整表证据集合

3. 让旧 cache 自动失效
   - 旧 `reader_compose_v7/v6` payload 会被判成 stale
   - compatible cache 不再跨 pipeline version 复用

## 当前原则

后续如果继续做高保真表格还原：

- 可以增强 `table_cells / rowspan / colspan`
- 也可以继续做 row-level / cell-level evidence

但不能再破坏这三件事：

1. `ActionBar` 必须继续有 `证据`
2. `withAnchorPreview(TablePanel)` 必须继续生效
3. whole-table evidence flow 必须优先于表格特例交互
