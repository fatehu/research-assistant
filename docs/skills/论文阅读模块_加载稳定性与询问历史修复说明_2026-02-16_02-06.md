# 论文阅读模块：加载稳定性与询问历史修复说明（2026-02-16 02:06）

## 1. 改造目标
- 修复阅读工作台进入后 PDF 长时间转圈/加载失败。
- 完成上轮评审遗留的 5 个问题闭环：
  1. 前端依赖漂移
  2. `GET /papers/{id}/pdf` 读接口副作用
  3. 本地缓存缺失
  4. 询问历史读取能力缺失
  5. 自动化测试缺失

## 2. 关键技术与实现
### 2.1 后端 PDF 读链路去副作用
- 文件：`backend/app/api/literature.py`
- 将 `GET /api/v1/literature/papers/{paper_id}/pdf` 调整为“只读流式返回”。
- 不再在 GET 接口中触发下载与数据库写入，避免页面首开被远端下载阻塞。
- 新增 `_build_paper_pdf_file_path`、`_resolve_local_pdf_path` 统一路径解析，下载链路与入库链路共用。

### 2.2 询问历史读取 API
- 文件：`backend/app/api/literature.py`
- 新增：
  - `GET /api/v1/literature/ask/sessions`
  - `GET /api/v1/literature/ask/sessions/{session_id}/messages`
- 权限策略：仅当前用户可读写自己的会话/消息。
- 消息返回时统一做 `sources` 清洗，保障结构稳定。

### 2.3 前端阅读器稳定性与缓存
- 文件：`frontend/src/pages/literature/PaperReaderPage.tsx`
- PDF 加载链路：
  1. 先请求本地 PDF Blob
  2. 若失败则显式调用 `download-pdf`
  3. 再次拉取 Blob
  4. 仍失败则给出明确错误，不再退化到跨域远程 `pdf_url`（避免 network error 假死）
- 新增本地缓存键：
  - `lit:reader:{user_id}:{paper_id}`
  - `lit:annotation:draft:{user_id}:{paper_id}`
  - `lit:ask:draft:{user_id}:{paper_id}`
- 新增询问历史 UI：会话下拉、消息记录区，并支持会话回放。

### 2.4 前端 API 类型与方法扩展
- 文件：`frontend/src/services/api.ts`
- 新增类型：`LiteratureAskSession`、`LiteratureAskMessage`
- 新增方法：
  - `getAskSessions`
  - `getAskMessages`

### 2.5 Docker 前端依赖漂移修复
- 文件：`docker-compose.yml`
- `frontend` 启动命令调整为：先执行 `npm install --no-audit --no-fund` 再启动 Vite。
- 目标：解决命名卷 `node_modules` 在依赖变更后未同步导致的运行时缺包问题（如 `react-pdf`）。

## 3. 可感知效果
- 阅读页首开不再因 GET 触发隐式下载而长时间阻塞。
- PDF 缺失时给出可执行错误提示，避免“转圈无反馈”。
- 询问面板可查看并切换历史会话，历史仅本人可见。
- 阅读位置、批注草稿、提问草稿在刷新后可恢复。

## 4. 风险与回滚
- 风险：`frontend` 每次容器启动会执行 `npm install`，启动时长增加。
- 回滚方式：
  1. 恢复 `docker-compose.yml` 前端 command。
  2. 恢复 `PaperReaderPage.tsx` 加载与缓存逻辑。
  3. 恢复 `literature.py` 的 `/pdf` 路由实现与 ask history 新接口。
