# 全量整改阶段07：前后端状态与错误契约对齐实施说明

- 时间：2026-02-23 10:58
- 阶段目标：在前端统一解析后端结构化错误体，并兼容新旧状态枚举，降低状态/错误语义分叉。
- 关联 commit：`chore(contract): 前后端状态与错误契约对齐`

## 本阶段改动
1. 在 `frontend/src/services/api.ts` 引入统一契约类型：
   - `ApiErrorContract` / `ApiErrorDetail`
   - `TaskStatus`
2. 新增工具函数：
   - `extractApiErrorMessage(detail, fallback)`：统一提取错误文案。
   - `normalizeTaskStatus(...)`：统一状态归一化（兼容 `processing/running/ready/success/done/...`）。
   - `normalizeDocumentStatus` / `normalizeKnowledgeLinkStatus`。
3. Axios 响应拦截器接入错误归一化：支持 `detail` 为字符串或结构化对象。
4. SSE/流式接口错误解析改造：`streamJsonSse`、聊天流、文献问答流统一使用 `extractApiErrorMessage`。
5. 类型对齐：
   - `Document.status` 与 `PaperKnowledgeLink.status` 增补 `running/timeout/cancelled` 等兼容值。
   - `AgentChatEvent` 增加 `error_contract` 字段，接收后端工具失败结构化诊断。
6. 页面适配：
   - `frontend/src/pages/knowledge/utils.tsx` 增加 `running/ready/timeout/cancelled` 状态标签。
   - `frontend/src/pages/knowledge/KnowledgePage.tsx` 轮询判定包含 `running`。
   - `frontend/src/pages/literature/PaperReaderPage.tsx` 使用 `normalizeKnowledgeLinkStatus` 驱动轮询与状态颜色。

## 设计取舍
1. 采用“前端兼容优先”策略：先支持新旧状态并存，再逐步收口到单一枚举。
2. 不在本阶段大规模改造业务组件错误提示逻辑，优先统一底层 API 层。

## 风险与回滚
1. 风险：低。主要为类型扩展与解析策略增强。
2. 回滚：可单 commit 回滚，不影响数据库与后端接口。

## 效果感知
1. 错误提示从“弱结构字符串”升级为“结构化契约优先解析”。
2. 前端对状态值变体的容错提升，减少“后端有状态但前端判定遗漏”。
