# MCP阶段3登录态E2E闭环说明

- 记录时间：2026-02-13 06:08
- 目标：把“登录后 MCP 配置页可操作”升级为“可自动化验证的保存+探测闭环”，避免人工点测和假通过。

## 本次使用的技术

1. Playwright CLI 自动化（函数式 `run-code`）
- 在 `e2e/mcp_settings_login_e2e.ps1` 中统一封装 `Invoke-PlaywrightCli` 与 `Invoke-PlaywrightCode`。
- 使用函数式代码片段（`async (page) => { ... }`）驱动登录、路由跳转、按钮操作与断言。

2. 登录态 E2E 闭环编排
- 动态创建测试账号（调用后端注册接口）。
- 进入 `/settings` 后执行 `Apply Template -> Validate -> Save -> Refresh Status`。
- 对 MCP 关键接口增加 2xx 级别断言（不是仅判断 `<500`）。

3. 假成功防护
- Playwright CLI 即使出现 `### Error` 也可能返回 0。
- 在脚本里增加输出扫描：检测到 `### Error` 或 `error:` 即主动抛错，防止误判通过。

4. 容器开发态一致性修正
- 发现 Vite 实时模块仍是旧版 `SettingsPage`，通过重启 `research_frontend` 使新模块生效。
- 复测确认 `SettingsPage` 实际加载 MCP 配置面板。

5. 运行产物治理
- 将 `.playwright-cli/`、`output/`、`backend/mcp_servers.json` 纳入 `.gitignore`，避免把临时与运行态文件带入版本库。

## 目的是什么

- 让 Phase 3 的 MCP 配置能力具备可回归验证能力。
- 把“接口被调用”提升为“接口成功（2xx）且页面状态渲染正确”。

## 怎么用的

1. 执行命令：
- `powershell -ExecutionPolicy Bypass -File e2e/mcp_settings_login_e2e.ps1`

2. 脚本默认地址参数：
- 前端：`http://localhost:3000`
- 后端：`http://localhost:8888`

3. 成功后产物：
- 截图：`output/playwright/mcp-settings-login-e2e.png`
- 最新 snapshot：`.playwright-cli/page-*.yml`

## 做到了什么

- 登录态下完成 MCP 配置页完整操作链路并自动断言通过。
- `validate/save/refresh` 都按 2xx 成功返回。
- 修复了此前“脚本退出成功但中途语法错误/400 仍被判通过”的问题。

## 怎么感知效果

1. 运行脚本后终端输出 `E2E completed successfully.`。
2. 截图显示用户已在 `/settings`，且 MCP 区域可见。
3. 脚本失败会在出错步骤立即停止，不再出现假阳性通过。

## 怎么测试

- 自动化主测：反复执行 `e2e/mcp_settings_login_e2e.ps1`。

- 回归重点：`/api/mcp/config/validate`、`/api/mcp/config`、`/api/mcp/status/refresh` 必须返回 2xx。
