# 论文阅读 Read 公式误判启发式收敛说明

时间：2026-03-13 09:28

## 背景

`/read` 的 `layout_uid_v1` 在 live 请求未稳定拿到页图时，会退回 fallback 组装链。`paper 85 / page 8` 暴露出一类问题：普通量化配置列表被误判成 `EquationBlock`，正文里因此出现错误的“公式截图”展示。

已确认的误判样本包括：

- `1. llama.cpp6 for 4-bit(Q4K_M), 3-bit(Q3_K_M), 2-bit (Q2_K), and 8-bit (Q8_0) configurations`
- `2. Unsloth7 for specialized dynamic 2-bit quantization (Q2K_XL)`
- `·4-bit:Q4-K_M (llama.cpp)`
- `·DeepSeek-R1 2-bit: Large-scale UD-Q2_K_XL (unsloth)`

## 根因

- 误判发生在 fallback 的 `_classify_grounding_node_kind(...)` / `_looks_like_equation_text(...)`
- 当前公式启发式把 `-`、`_`、括号里的量化配置和框架名一起算进了“像公式”的特征
- page 8 当前实际走的是 fallback，因此该启发式直接影响页面输出

## 本轮修复边界

只处理：

- fallback 里的公式启发式过宽
- 量化配置列表、编号项、bullet 项不再判成 `equation`

不处理：

- 全局 evidence preview 主链
- page 8 页图本地化 `HTTP 403` 问题
- 正式 AI grouping / table logical rows / `/experience`

## 目标

- `Q4_K_M / Q2K_XL / BF16 / FP8 / llama.cpp / unsloth / Tencent API / Reported` 这类配置文本不再进入 `EquationBlock`
- 真实公式文本（例如 `y = mx^2 + b`）继续被判成 `equation`

## 已实施

- 在 `backend/app/services/literature_reader_compose_service.py` 中新增 `_looks_like_quantization_config_text(...)`
- `_looks_like_equation_text(...)` 现在会先排除量化配置列表/编号项/bullet 项
- 收紧了文本启发式里的数学符号计数，不再把 `-`、`_` 这类配置名分隔符当成公式证据
- 将 compose 版本升级到 `reader_compose_v13`，使旧的 page 8 错误 fallback 缓存失效

## 运行态结论

对 `paper 85 / page 8` 的 fresh rebuild 结果：

- `status = fallback`
- `engine_version = reader_compose_v13`
- 已不再产出错误的 `EquationBlock`
- 原本误判为公式的几组内容现在回到 `ListBlock`

## 回退方式

若本轮收窄导致真实公式漏判：

1. 回退本次提交
2. 仅恢复 `_looks_like_equation_text(...)` 和对应测试
3. 不影响 `/read` 其他链路
