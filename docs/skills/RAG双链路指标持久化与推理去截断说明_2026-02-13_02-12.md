# RAG双链路指标持久化与推理去截断说明

- 记录时间：2026-02-13 02:12
- 适用范围：AI对话（/api/chat/send）、CodeLab/Notebook Agent（/api/codelab/notebooks/{id}/agent/chat 与 /api/codelab/notebooks/{id}/agent/history）

## 1. 本次更新解决的问题
1. AI 对话链路虽然可在 SSE `done` 中返回 `rag_metrics`，但未写入数据库，刷新后消息丢失 RAG 质量指标。
2. Notebook/CodeLab Agent 的历史仅在内存，重启服务或刷新后不可追溯，也无法稳定复用历史中的 `rag_metrics`。
3. ReAct observation 在后端与前端存在多处截断（`[:500]`、`[:2000]`、`substring(0, 200)`、`slice(0, 300)`），导致来源内容在推理过程无法完整参考。

## 2. 使用的技术与实现方式
1. 新增 Notebook Agent 历史持久化服务：`backend/app/services/notebook_agent_history_service.py`
- 通过 Notebook 的 `metadata` JSON 字段持久化 agent 历史，统一键为 `agent_histories`。
- 采用 channel 区分不同 agent：`codelab`、`notebook_agent`。
- 提供 `load_history/persist_history/append_history_message/clear_history` 统一能力。

2. CodeLab Agent 持久化接入：`backend/app/api/codelab.py`
- `get_agent_history/save_agent_message/clear` 改为异步并接入 DB 服务。
- 保留内存缓存 `_agent_histories`，同时每次写入同步落盘。
- assistant 消息 `metadata` 增加 `rag_metrics` 持久化。

3. Notebook Agent 持久化接入：`backend/app/api/notebook_agent.py`
- 历史读写改为异步并接入 DB 服务（按 `user_id:notebook_id` 维度隔离）。
- `history/clear/tools/chat` 路由统一改用 `get_notebook_cached`，确保数据库存在性校验一致。
- assistant 消息 `metadata` 增加 `rag_metrics` 持久化。

4. AI 对话链路补齐持久化：`backend/app/api/chat.py`
- assistant 消息保存时写入 `metadata_={"rag_metrics": rag_metrics}`。

5. 去截断改造（推理链路）
- 后端：`backend/app/services/react_agent.py` 删除 observation `[:2000]`。
- 后端：`backend/app/api/notebook_agent.py` 删除 observation `[:500]`。
- 后端：`backend/app/api/codelab.py` 删除 `react_output_max_length` 截断。
- 前端：`frontend/src/components/NotebookAgentPanel.tsx` 删除 `substring(0, 200)`。
- 前端：`frontend/src/pages/chat/components/ReActPanel.tsx` 删除 `slice(0, 300)`。
- 前端：`frontend/src/pages/chat/components/HistoryReActPanel.tsx` 保持 observation 全量展示。
- 前端：`frontend/src/pages/chat/components/MessageBubble.tsx` 与 `frontend/src/components/NotebookAgentPanel.tsx` 的来源标签改为可换行（`break-all`）。

## 3. 做到了什么
1. Chat 与 Notebook/CodeLab 两套 Agent 都具备 RAG 质量指标展示与持久化基础。
2. 历史恢复后可继续读取 `metadata.rag_metrics`，不再依赖“仅本次流式会话”。
3. 推理链路 observation 不再被固定长度裁剪，来源文本可完整审阅。

## 4. 如何使用
1. 前端开关：`VITE_SHOW_RAG_METRICS=true`（在 `.env` 中设置并让前端 dev 服务重载）。
2. 发起会触发知识检索的问答后，在 assistant 消息中展开 `RAG质量`。
3. 刷新页面后重新加载历史消息，确认指标仍可见（来自持久化 metadata）。

## 5. 如何感知效果
1. 直接感知：历史消息中不再“丢失 RAG 质量面板”。
2. 可解释性提升：推理过程中的 observation 来源文本可完整查看，不再被截断。
3. 追踪能力提升：可跨会话复盘检索调用次数、引用有效性、压缩命中/回退等指标。
