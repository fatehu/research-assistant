# 前端工程化阶段1：ESLint 基线接入

- 记录时间：2026-02-13 18:00
- 阶段目标：打通 `npm run lint`，让前端项目具备可执行的静态检查基线。

## 1. 使用了哪些技术
- ESLint 传统配置文件：`.eslintrc.cjs`
- TypeScript 解析器与插件：
  - `@typescript-eslint/parser`
  - `@typescript-eslint/eslint-plugin`
- React 规则插件：
  - `eslint-plugin-react-hooks`
  - `eslint-plugin-react-refresh`
- 忽略文件配置：`.eslintignore`

## 2. 目的是什么
- 解决前端仓库“无 ESLint 配置导致 lint 命令直接失败”的问题。
- 建立可运行的 lint 基线，保证后续能稳定纳入开发流程。

## 3. 怎么用
- 在前端目录执行：
  - `npm run lint`
- 当前规则策略：
  - 允许输出 warnings（尤其是 `react-hooks/exhaustive-deps`）
  - 将阻断型规则错误降级/关闭，优先保证命令可运行

## 4. 做到了什么
- `npm run lint` 从“直接失败”变为“可执行并返回 0”。
- `dist`、`node_modules` 等目录被排除，避免无效扫描。
- 现有代码可在不大规模重构的前提下稳定通过 lint 命令。

## 5. 怎么感知效果
- 执行 `npm run lint` 不再报 “找不到 ESLint 配置文件”。
- 命令输出仅剩 warnings，不再有 errors 阻断流程。

## 6. 怎么测试
- 前端静态检查：
  - `cd frontend && npm run lint`
- 前端构建回归：
  - `cd frontend && npm run build`
