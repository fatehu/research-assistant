# 检索性能优化阶段6：前端可感知闭环

- 记录时间：2026-02-13 17:50
- 阶段目标：将已落地的检索优化能力（压缩、改写、维度守卫、相邻上下文）完整映射到前端搜索体验，保证用户可感知。

## 1. 本次使用了哪些技术
- 前端请求参数透传扩展（TypeScript 接口 + API 请求体映射）
  - `KnowledgeSearchOptions` 新增：
    - `rewriteMode`
    - `includeAdjacentChunks`
    - `adjacentWindow`
- 检索默认策略调优（知识库搜索页）
  - 默认开启 `Contextual Compression`
  - 默认关闭相邻上下文，窗口默认 `1`
- 结果可观测信息渲染
  - 在搜索结果卡片展示检索元信息：
    - `retrieval_dimension`
    - `query_rewrite_cache_hit`
    - `query_rewrite_skip_reason`
    - `query_rewrite_llm_called`
    - `contextual_compression_enabled`
    - `contextual_compression_fallback`
- 相邻上下文（adjacent context）可视化
  - 读取并渲染 `metadata.adjacent_context`
  - 显示偏移、chunk 编号、层级、章节标题、内容

## 2. 目的是什么
- 让检索优化从“后端能力”变成“前端可感知体验”。
- 减少用户对检索行为的黑盒感，提升可解释性与调参效率。
- 保持 API 链路与 Agent Tool 链路协议一致，不新增分叉。

## 3. 怎么用
- 知识库搜索弹窗「高级过滤」可直接配置：
  - Query Rewrite / Hybrid / Reranker / Contextual Compression
  - 相邻上下文开关与窗口大小（1-3）
- 搜索结果卡片可查看：
  - 检索元信息
  - 相邻上下文
  - 父级上下文（保留）
- 环境可见性策略：
  - `.env.example` 保持 `VITE_SHOW_RAG_METRICS=false`
  - 开发环境通过 `.env` 设置 `VITE_SHOW_RAG_METRICS=true`

## 4. 做到了什么
- 前端到后端的检索参数透传闭环完成，包含相邻上下文参数。
- 知识库搜索默认策略落地为“平衡默认”：
  - 压缩默认开
  - 相邻上下文默认关
- 搜索结果新增检索可观测信息展示，不再只能看最终正文片段。
- 形成“父级上下文 + 相邻上下文”的双视图。

## 5. 怎么感知效果
- 用户可以在同一张结果卡片直接看见：
  - 当前结果使用的向量维度
  - 改写是否命中缓存、是否跳过、是否调用 LLM
  - 压缩是否启用、是否走回退
- 打开相邻上下文后，可看到命中块前后窗口内容，便于确认上下文完整性。
