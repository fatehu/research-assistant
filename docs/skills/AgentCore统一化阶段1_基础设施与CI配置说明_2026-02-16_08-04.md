# AgentCore统一化阶段1：基础设施与CI配置说明（2026-02-16 08:04）

## 1. 本阶段目标
- 修复 CI 与本地 Docker GPU 配置冲突，避免 PR/Nightly 因 `CODELAB_RUNNER_TOKEN` 或 GPU 资源导致失败。
- 补齐论文阅读 Agentic 模式的独立迭代参数，避免与全局 ReAct 迭代次数耦合。

## 2. 改动文件白名单
- `.env.example`
- `.github/workflows/nightly-e2e-full.yml`
- `.github/workflows/pr-api-smoke.yml`
- `.github/docker-compose.ci.yml`
- `backend/app/config.py`
- `docker-compose.yml`

## 3. 使用技术与做法
- Docker Compose 多文件覆盖：CI 通过 `.github/docker-compose.ci.yml` 覆盖 backend 的 `gpus` 配置。
- GitHub Actions 流水线增强：统一使用 `-f docker-compose.yml -f .github/docker-compose.ci.yml`。
- 参数化配置：新增 `LITERATURE_AGENT_MAX_ITERATIONS`（默认 8）。

## 4. 达成效果
- CI 不再依赖本地 GPU 默认配置；可在无 GPU Runner 环境稳定启动。
- Nightly/PR 工作流补齐产物目录准备，避免“无文件可上传”的告警。
- 文献询问 Agentic 模式可独立调优步数，不影响全局 Agent。

## 5. 风险与回滚
- 若 CI 特殊环境需要 GPU，可移除覆盖文件中的 `gpus: []`。
- 若新增迭代参数引发行为偏差，可回落使用 `react_max_iterations`。
