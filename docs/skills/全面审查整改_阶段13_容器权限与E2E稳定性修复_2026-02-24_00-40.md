# 全面审查整改_阶段13_容器权限与E2E稳定性修复

- 记录时间：2026-02-24 00:40
- 分支：`feature/full-remediation-2026-02`
- 目标：在保持 Docker 非 root 基线的前提下，打通上传/MCP配置写入权限，并消除角色路由 E2E 的高频不稳定点。

## 背景问题
1. `remaining_modules_api_smoke_e2e.ps1` 在知识库上传阶段失败，后端日志显示 `PermissionError: /app/uploads/<user_id>`。
2. `mcp_settings_login_e2e.ps1` 在保存 MCP 配置阶段失败，后端日志显示 `PermissionError: mcp_servers.json`。
3. `role_route_smoke_e2e.ps1` 使用 `playwright-cli open <login-url>` 时出现间歇性 `Target page closed / Timeout / ERR_EMPTY_RESPONSE`。

## 实施改动
1. 容器启动权限收敛（保持非 root）
- 重写 `backend/Dockerfile` 为干净 UTF-8 内容，新增 `gosu`。
- 新增 `backend/docker-entrypoint.sh`：
  - 启动时修复 `/app/uploads`、`/app/model_cache` 权限。
  - 启动时按 `MCP_CONFIG_PATH` 自动创建并授权配置文件。
  - 最终通过 `gosu app` 降权执行主进程。

2. E2E 稳定性修复
- 更新 `e2e/role_route_smoke_e2e.ps1`：
  - 新增 `Invoke-PlaywrightOpenWithRetry`。
  - 流程改为先 `open about:blank`，再 `run-code` 跳转登录页，规避 direct-open 不稳定。

## 验证摘要
1. `docker compose up -d --build backend codelab-runner` 通过。
2. `remaining_modules_api_smoke_e2e.ps1` 由失败恢复为通过。
3. `mcp_settings_login_e2e.ps1` 由失败恢复为通过。
4. `role_route_smoke_e2e.ps1 -Role mentor/admin` 在脚本修复后通过。

## 风险与回滚
1. 风险：入口脚本新增 `chown`，容器启动耗时略增。
2. 风险：`MCP_CONFIG_PATH` 指向只读路径时，仍可能失败（已做 best-effort 处理）。
3. 回滚：回退 `backend/Dockerfile`、`backend/docker-entrypoint.sh`、`e2e/role_route_smoke_e2e.ps1` 到上一提交并重建容器。
