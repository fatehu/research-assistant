# 论文阅读 Read 恢复整表证据链与 DocMind 高光说明

时间：2026-03-12 18:55

## 背景

`/read` 在引入表格重建后的 `row_evidence / cell_evidence` 交互时，证据链从原本稳定的：

- `source_layout_ids`
- `source_atom_ids`
- `page_grounding_v1.evidence_map`
- `uniqueId -> blocks[].pos`

变成了以表格行/单元格临时锚点为主的前端交互模型。结果是：

- 表格 `...` 菜单中的 `证据` 容易消失或行为异常
- hover 证据预览不再稳定
- 整表回溯被切碎为 row/cell 级局部交互
- caption 与 table bundle 的回溯语义被拆散

这违背了 `/read` 当前的目标：稳定的 HTML 式流式阅读、AI 清洗正文、简化 AI 排版、强证据溯源。

## 恢复目标

恢复到表格重建前更稳的行为模型：

- `/read` 的表格仍可以保留更好的 HTML 展示
- 但证据链回到整表节点级
- hover 由整个 `TablePanel` 触发
- 菜单中的 `证据` 由通用 `ActionBar` fallback 行为提供
- 高光与预览统一信任 `source_layout_ids/source_atom_ids -> page_grounding_v1 -> blocks[].pos`

## 具体调整

### 1. 后端恢复 table bundle 的完整 `source_layout_ids`

在 `layout_uid_v1` 的 `group_plan -> panel_plan` 物化阶段，不再对 `table` 节点做“只保留表体 layout、排除 caption layout”的特判。

恢复后：

- `TablePanel.source_layout_ids` 保留整个 table bundle
- `TablePanel.source_atom_ids` 与之保持一致
- 预览与跳转重新以完整 bundle 为单位

### 2. 前端移除 row/cell 级表格证据交互

`TablePanel` 不再：

- 行 hover 触发单独证据
- 单元格 click 触发单独证据
- 在卡片顶部额外提供独立的 `证据 / 预览` 按钮

而是恢复为：

- `withAnchorPreview` 负责整表 hover
- `ActionBar` 的通用 `jump_anchor` fallback 负责 `证据`
- 表格节点只额外保留导出操作

### 3. 保留更好的展示，但不再让它主导证据链

保留：

- `table_cells`
- `matrix`
- caption/notes
- 稍微更接近论文的表格视觉

但这些只服务展示，不再改变证据链的主键和主行为。

## 当前原则

`/read` 的证据链优先级：

1. `uniqueId(source_layout_id)`
2. `page_grounding_v1.evidence_map[*].block_positions`
3. `DocMind blocks[].pos`
4. 只有极端情况下才退回旧 block 级兼容锚点

表格、公式、正文段落都要尽量服从这条原则，不再各自发明独立的 evidence 行为。
