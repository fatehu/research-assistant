# 检索性能优化阶段7：弹性维度与长查询可见性

- 记录时间：2026-02-13 21:00
- 阶段目标：将检索向量维度从手动配置升级为按知识库规模自动弹性选择，同时修复长查询“后端有结果但前端无感知”的体验断点，打通 API 与 Agent Tool 双链路。

## 1. 本次使用了哪些技术
- 向量维度自适应策略服务（`embedding_dimension_policy_service`）
  - 按 chunk 规模自动选择 `256 / 512 / 模型默认维度`
  - 引入阈值抖动保护（hysteresis）
- 动态维度向量存储与索引
  - `document_chunks.embedding` 从固定 `vector(1024)` 改为 `vector`
  - 新增 256/512/1024 三套 HNSW 表达式索引
- 后台异步维度重建服务（`dimension_rebuild_service`）
  - 维度跨阈值时异步重嵌入与状态写回
  - 重建后自动触发 recall gate 并写入报告路径
- 检索链路按 `(embedding_model, embedding_dimension)` 分组
  - API 链路与 Agent Tool 链路统一改造
  - `ef_search` 改为按分组语料规模和维度独立计算
- 前端长查询可见性闭环
  - 搜索默认超时提升到 `300000ms`
  - 请求可取消（`AbortController`）
  - 阶段提示（编码中/检索候选中/重排压缩中/深度处理中）
  - 主请求超时后自动降级重试（关闭 rewrite/reranker/compression）

## 2. 目的是什么
- 让维度策略“弹性自动化”而不是人工调参。
- 在不牺牲在线可用性的前提下，支持规模增长后的维度平滑切换。
- 让用户在超长查询中始终获得清晰反馈、可取消控制和降级可见结果。

## 3. 怎么用 / 怎么落地
- 后端默认开启自适应策略（见 `.env.example`）：
  - `EMBEDDING_DIMENSION_POLICY=adaptive`
  - `EMBEDDING_DIM_SMALL=256`
  - `EMBEDDING_DIM_MEDIUM=512`
  - `EMBEDDING_DIM_SMALL_MAX_CHUNKS=2000`
  - `EMBEDDING_DIM_MEDIUM_MAX_CHUNKS=10000`
  - `EMBEDDING_DIM_HYSTERESIS_ENABLED=true`
  - `EMBEDDING_DIM_REBUILD_ASYNC=true`
- 长查询体验默认配置：
  - `SEARCH_TIMEOUT_PRIMARY_MS=300000`
  - `SEARCH_TIMEOUT_FALLBACK_MS=90000`
  - `SEARCH_TIMEOUT_AUTO_FALLBACK=true`
- 前端无需新增入口；在知识库搜索弹窗直接生效：
  - 搜索中可见阶段提示与耗时
  - 可主动取消
  - 超时自动降级重试并显示“降级结果”标识

## 4. 做到了什么
- 实现了 KB 规模驱动的维度选择与后台异步重建，不阻塞当前请求。
- API 与 Agent Tool 检索均支持多维度混部检索并统一融合返回。
- 检索元信息可返回并展示降级重试状态：
  - `fallback_retry_used`
  - `fallback_retry_reason`
- 维持现有 recall gate 体系，并在重建后自动触发记录。

## 5. 怎么感知效果
- 用户在前端可直接感知：
  - 长查询不再 90 秒即“无响应”，可等待到 300 秒并随时取消
  - 若主请求超时，会自动切换低开销策略重试并给出降级标识
  - 检索卡片可识别是否经过超时降级路径
- 运维可感知：
  - 重建状态、重建报告路径、recall gate 结果可追踪
