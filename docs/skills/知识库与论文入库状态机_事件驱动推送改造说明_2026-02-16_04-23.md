# 知识库与论文入库状态机：事件驱动推送改造说明（2026-02-16 04:23）

## 1. 阶段目标
- 将高频轮询（知识库文档状态、论文入库状态）改造为事件驱动推送。
- 在论文阅读页同步接入实时状态更新，减少“处理中卡住但 UI 不刷新”的体感问题。
- 保留低频轮询兜底，防止 SSE/网络异常导致状态不可见。

## 2. 核心改造

### 2.1 后端事件总线（Redis + 本地回退）
- 新增文件：`backend/app/services/status_event_bus.py`
- 能力：
  - 优先 Redis Pub/Sub 发布/订阅状态事件。
  - Redis 不可用时回退进程内队列。
  - 提供统一接口：
    - `build_status_channel_for_user(user_id)`
    - `publish_status_event(channel, payload)`
    - `iter_status_events(channel, heartbeat_seconds)`

### 2.2 知识库状态事件发布与 SSE 接口
- 文件：`backend/app/api/knowledge.py`
- 新增接口：`GET /api/v1/knowledge/events/stream`（SSE）
  - 可选参数：`kb_id`
  - 事件类型：`connected` / `heartbeat` / `document_status`
- 状态发布时机：
  - 文档上传创建为 `pending` 后
  - 后台任务切换到 `processing` 时
  - 处理失败（含文本为空、分块失败、异常兜底）时
  - 处理完成 `completed` 时
  - 状态超时守卫将文档打为 `failed` 时

### 2.3 文献入库状态事件发布与 SSE 接口
- 文件：`backend/app/api/literature.py`
- 新增接口：`GET /api/v1/literature/events/stream`（SSE）
  - 可选参数：`paper_id`
  - 事件类型：`connected` / `heartbeat` / `paper_link_status`
- 状态发布时机：
  - `add-to-knowledge` 创建/更新 link 为 `pending`
  - 后台入库任务置为 `processing`
  - 后台入库任务最终落为 `ready/failed`
  - `knowledge-links` 查询接口轻量同步状态后发生变化时

### 2.4 前端 API 订阅能力
- 文件：`frontend/src/services/api.ts`
- 新增：
  - `streamJsonSse(...)` 通用流解析器
  - `knowledgeApi.streamStatusEvents(...)`
  - `literatureApi.streamStatusEvents(...)`
- 新增类型：
  - `KnowledgeDocumentStatusEventData`
  - `PaperKnowledgeLinkStatusEventData`

### 2.5 知识库页面改造（轮询 -> 事件驱动）
- 文件：`frontend/src/pages/knowledge/KnowledgePage.tsx`
- 改造：
  - 进入知识库后订阅状态流，收到 `document_status` 直接更新 Zustand 文档状态。
  - 原 3 秒轮询降级为 30 秒低频兜底（仅存在 pending/processing 文档时触发）。
- 文件：`frontend/src/stores/knowledgeStore.ts`
  - 新增 `applyDocumentStatusPatch(...)`，避免每次事件都再发 GET 请求。

### 2.6 论文阅读页同步改造
- 文件：`frontend/src/pages/literature/PaperReaderPage.tsx`
- 改造：
  - 订阅文献状态流，收到 `paper_link_status` 实时更新右侧“评分/入库”中的 link 状态。
  - 增加 30 秒低频兜底拉取（仅当存在 pending/processing link）。

## 3. 设计取舍
- 取舍 1：优先事件驱动，保留低频轮询兜底。
  - 原因：纯事件流在网络异常下会出现“静默中断”，兜底轮询用于补偿可靠性。
- 取舍 2：事件按 `user` 维度分频道。
  - 原因：隔离简单，权限边界清晰，避免跨用户事件泄露。

## 4. 可感知效果
- 知识库文档处理列表不再每 3 秒狂刷状态接口。
- 论文阅读页“加入知识库”后状态可自动推进到 `processing/ready/failed`。
- 在 Redis 不可用时功能仍可运行（本地队列回退）。

## 5. 风险与回滚
- 风险：SSE 连接受代理/网络环境影响可能中断。
- 缓解：已保留 30 秒低频轮询兜底。
- 回滚：
  1. 回退 `KnowledgePage.tsx` 与 `PaperReaderPage.tsx` 的 SSE 订阅逻辑。
  2. 回退 `api.ts` 的 stream API。
  3. 仅保留原轮询方案。
