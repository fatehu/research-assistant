# PGVector HNSW 索引优化说明（2026-02-12）
- 记录时间：2026-02-12 21:01

## 1. 本次使用的技术
- PostgreSQL + pgvector `hnsw` ANN 索引
- Alembic 迁移（`CREATE INDEX CONCURRENTLY` 并发建索引）
- SQL 会话级检索参数调优：`hnsw.ef_search`
- 检索链路性能保护：设置失败自动降级，不阻断主流程

## 2. 目的是什么
- 解决向量检索在数据量增长后的线性变慢问题。
- 在不改变业务接口的前提下，把默认精确扫描切换到可扩展的 ANN 检索路径。
- 在速度和召回之间提供可配置平衡（`ef_search`）。

## 3. 怎么用（接入方式）
### 3.1 数据库迁移
- 新增迁移：`backend/alembic/versions/009_hnsw_index_concurrently.py`
- 升级逻辑：
  - `DROP INDEX CONCURRENTLY IF EXISTS idx_chunks_embedding_hnsw`
  - `CREATE INDEX CONCURRENTLY IF NOT EXISTS ix_chunks_embedding_hnsw ON document_chunks USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64)`

### 3.2 查询参数调优
- 新增配置项：
  - `backend/app/config.py`：`pgvector_hnsw_ef_search: int = 40`
  - `.env.example`：`PGVECTOR_HNSW_EF_SEARCH=40`
  - `docker-compose.yml`：透传 `PGVECTOR_HNSW_EF_SEARCH`
- 新增通用函数：
  - `backend/app/services/vector_search_tuning.py`
  - 在当前事务执行：`SELECT set_config('hnsw.ef_search', :ef_search, true)`
  - 出错时仅告警并降级，不影响检索返回。

### 3.3 生效位置
- 知识库检索 API：`backend/app/api/knowledge.py`
- Agent 知识库工具：`backend/app/services/agent_tools.py`
- 两条检索链路都在向量查询前设置 `hnsw.ef_search`。

## 4. 做到了什么
- 将索引创建方式升级为并发，降低迁移锁表风险。
- 统一检索路径的 HNSW 搜索参数控制点，支持按环境调参。
- 保留失败降级能力，避免因为数据库参数不支持导致查询中断。

## 5. 怎么感知效果
- 结构层面：
  - `pg_indexes` 可看到 `ix_chunks_embedding_hnsw` 索引已存在。
- 运行层面：
  - 检索流程执行前会设置 `hnsw.ef_search`（默认 40）。
  - 可通过 A/B 对比检索耗时、召回质量（例如 `top_k` 命中相关段落比例）观察收益。
- 调参建议：
  - 提高 `PGVECTOR_HNSW_EF_SEARCH`：召回更稳，延迟更高。
  - 降低 `PGVECTOR_HNSW_EF_SEARCH`：延迟更低，召回可能下降。
