# 论文阅读工作台 V2：锚点定位与清晰度修复（2026-02-25 18:06）

## 背景
- 用户反馈 composed 证据定位不准、预览模糊、且希望“原文证据”放到批注区域下方。
- 质量面板多次出现 `max_iterations_reached`，需要验证是否因迭代预算过低导致效果不稳定。
- 当前模型为非多模态，定位链路应优先依赖文本锚点，而不是图像语义。

## 本次改动
1. 后端请求契约新增 `max_iterations`：
- `ReaderComposeRequest.max_iterations`（1-16）
- `ReaderComposePrefetchRequest.max_iterations`（1-16）
- API 路由透传 `max_iterations` 到 compose service 和 prefetch background。

2. Compose 生成循环增强：
- `build_or_get_composed_payload` 支持 `max_iterations`。
- `run_react_compose_loop` 支持覆盖轮次，默认从配置读取并做上下限约束。
- 将 `max_iterations` 纳入 `source_signature`，避免“调高轮次仍命中旧缓存”。

3. Compose service 稳定性与乱码修复：
- 修复多处损坏字符串导致的语法错误。
- 修复 `_should_merge_heading_lines` 中损坏正则。
- 修复外网资产校验逻辑中 `meta` 变量未定义（注释与代码粘连）问题。
- 修复 `_build_link_tldr` 逻辑：DOI 为空时不再误匹配全部链接。

4. 前端阅读页重构（围绕证据可信）：
- 证据预览从悬浮固定窗改为“批注工作区下方”卡片。
- 新增原始 PDF 局部高亮截图渲染链路。
- 锚点匹配优先级改为：`char_range > quote > bbox`。
- 证据图像输出调整为 `webp(0.86)`，提高感知清晰度同时控制体积。
- composed 请求固定下发：`quality_target=0.86`、`max_iterations=10`（可继续参数化）。
- `last_anchor` 增加 `compose_max_iterations` 持久化字段。

## 设计说明
- 非多模态模型场景下，文本坐标锚点是最稳定依据。
- `bbox` 只作为最后回退，避免高亮“看起来对，实际上错位”。
- 证据卡放在批注区可避免遮挡正文阅读流。
