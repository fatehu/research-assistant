# Query 改写检索增强说明（2026-02-12）

- 记录时间：2026-02-12 19:24

## 1. 本次使用的技术
- LLM Query Rewrite（三策略）：
  - 同义扩展（`synonym`）
  - HyDE 假设文档（`hyde`）
  - 子问题分解（`decompose`）
- 多查询召回聚合：同一请求内对多个改写 query 分别召回，再按分数去重合并（保留最高分命中）
- 混合检索与融合：`pgvector` + PostgreSQL FTS + RRF
- 可选精排：Cross-Encoder Reranker（沿用原有能力）
- 失败降级：改写失败/LLM不可用时自动回退原始 query

## 2. 目的是什么
- 解决用户 query 口语化、模糊、过宽导致的召回不足。
- 在不改动存储结构的前提下，提高检索召回覆盖率与相关性。
- 保持原有混合检索、RRF、Reranker 链路兼容。

## 3. 怎么用（使用方式）

### 3.1 配置项
- 全局开关与策略：
  - `ENABLE_QUERY_REWRITE=true`
  - `QUERY_REWRITE_STRATEGIES=synonym,hyde,decompose`
- 规模与时延控制：
  - `QUERY_REWRITE_MAX_SYNONYMS=3`
  - `QUERY_REWRITE_MAX_SUBQUERIES=3`
  - `QUERY_REWRITE_MAX_VARIANTS=8`
  - `QUERY_REWRITE_HYDE_MAX_CHARS=240`
  - `QUERY_REWRITE_TIMEOUT_SECONDS=12`
  - `QUERY_REWRITE_TEMPERATURE=0.2`

### 3.2 请求开关
- `POST /api/knowledge/search` 支持：
  - `use_query_rewrite`：是否启用 query 改写
  - `query_rewrite_strategies`：可选，按请求覆盖策略（`synonym/hyde/decompose`）

示例：
```json
{
  "query": "对比 CNN 和 Transformer",
  "top_k": 5,
  "use_hybrid": true,
  "use_reranker": true,
  "use_query_rewrite": true,
  "query_rewrite_strategies": ["synonym", "hyde", "decompose"]
}
```

## 4. 做到了什么（交付结果）
- 新增 `query_rewrite_service`，支持三种改写策略与超时/异常降级。
- `/api/knowledge/search` 改为“多改写 query 召回 -> 去重聚合 -> RRF -> 可选 Reranker”。
- Agent 的 `knowledge_search` 工具同步支持改写，避免链路能力不一致。
- 新增可观测字段：
  - `query_rewrite_enabled`
  - `query_rewrite_strategies`
  - `query_rewrite_fallback`
  - `matched_vector_query / matched_vector_strategy`
  - `matched_text_query / matched_text_strategy`

## 5. 怎么感知效果
- 直接看返回 metadata：是否出现 `matched_*` 与 `query_rewrite_*` 字段。
- 对比实验建议：
  - A：`use_query_rewrite=false`
  - B：`use_query_rewrite=true, query_rewrite_strategies=["synonym"]`
  - C：`use_query_rewrite=true, query_rewrite_strategies=["synonym","hyde","decompose"]`
- 关注指标：
  - `Recall@K`、`MRR@K`
  - top-K 结果可引用性
  - P95 检索延迟
