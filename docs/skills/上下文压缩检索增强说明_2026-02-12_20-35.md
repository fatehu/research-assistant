# 上下文压缩检索增强说明（2026-02-12）

- 记录时间：2026-02-12 20:35

## 1. 本次使用的技术
- LLM-based Contextual Compression（检索上下文压缩）
- Prompt Engineering（结构化压缩提示词 + 来源标签）
- 结果后处理（JSON/半结构化输出解析、相关度阈值过滤）
- ReAct Agent 观测值重写（在工具返回后、下一轮生成前压缩上下文）

## 2. 目的是什么
- 解决“长 chunk 直接喂给 LLM”导致的 token 浪费与噪声问题。
- 在 `Reranker` 之后、最终回答生成之前，只保留与 query 直接相关的句子。
- 让上下文天然带 `[来源X]` 标签，提升可引用性和可验证性。

## 3. 怎么用（使用方式）

### 3.1 配置项
- `ENABLE_CONTEXTUAL_COMPRESSION=true`
- `CONTEXTUAL_COMPRESSION_TIMEOUT_SECONDS=12`
- `CONTEXTUAL_COMPRESSION_TEMPERATURE=0.0`
- `CONTEXTUAL_COMPRESSION_MIN_RELEVANCE=4.0`
- `CONTEXTUAL_COMPRESSION_MAX_CHARS_PER_CHUNK=2200`
- `CONTEXTUAL_COMPRESSION_MAX_OUTPUT_TOKENS=400`
- `CONTEXTUAL_COMPRESSION_MAX_CONCURRENCY=3`

### 3.2 生效位置
- `ReAct Agent`：
  - 当工具为 `knowledge_search` 时，Agent 会对工具返回的 `results` 进行压缩，再把压缩后的 observation 注入下一轮推理。
- `POST /api/knowledge/search`：
  - 对 reranker 选中的候选块执行压缩，并将压缩结果写入返回 `metadata`。
  - `content` 优先返回压缩内容，若无有效压缩结果则回退原文。

## 4. 做到了什么（交付结果）
- 新增 `backend/app/services/contextual_compression_service.py`：
  - 支持单条/批量压缩；
  - 兼容 JSON 与非 JSON 模型输出；
  - 支持失败降级与低相关过滤。
- 改造 `backend/app/services/react_agent.py`：
  - 在 `knowledge_search` 的 observation 阶段自动压缩上下文后再进入下一轮生成。
- 改造 `backend/app/api/knowledge.py`：
  - 在 reranker 后加入压缩；
  - 在 metadata 中新增压缩相关字段（score/source/fallback/excerpt）。
- 新增配置：
  - `backend/app/config.py`
  - `.env.example`
  - `docker-compose.yml`

## 5. 怎么感知效果
- 在 Agent 的中间观测信息中，可看到压缩后的短上下文（含 `[来源X]`）。
- 检索 API 返回中可观察：
  - `metadata.contextual_compression_enabled`
  - `metadata.contextual_compression_source`
  - `metadata.contextual_compression_score`
  - `metadata.contextual_compression_fallback`
  - `metadata.contextual_compression_excerpt`
- 预期效果：
  - prompt token 降低；
  - 回答中的无关引用减少；
  - 溯源可读性提升。
