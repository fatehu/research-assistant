# 全量整改阶段04：Agent 工具失败协议统一与可维护性优化实施说明

- 时间：2026-02-23 10:47
- 阶段目标：在 `react_agent.py` 与 `registry.py` 之间统一工具失败回传协议，降低调用链语义分叉。
- 关联 commit：`refactor(agent): 拆分 registry/react_agent 并统一工具调用失败协议`

## 本阶段改动
1. 新增 `backend/app/services/agent_tool_error_contract.py`：
   - `build_tool_error_contract`：构建统一错误契约（`code/message/tool/stage/detail/retryable/metadata`）。
   - `merge_error_contract`：将契约写入 `ToolResult.data.error_contract`。
2. 在 `backend/app/services/agent_tools_impl/registry.py` 中接入统一失败协议：
   - 参数校验失败、超时、执行异常、dispatch 异常、工具不存在均输出统一 `error_contract`。
   - 保持原 `ToolResult` 外层字段兼容（`success/output/error/data`），避免下游断裂。
3. 在 `backend/app/services/react_agent.py` 中接入统一失败协议：
   - 工具调度异常时返回带 `error_contract` 的 `ToolResult`。
   - observation 事件新增 `error_contract` 字段，供前端/日志系统做结构化诊断。
4. 新增 `backend/tests/test_agent_tool_error_contract.py` 覆盖契约构建与合并逻辑。

## 设计取舍
1. 采用“新增契约 + 渐进接入”方式，不重构 `ToolResult` 主结构，降低兼容风险。
2. 保留原 `output/error` 文本，兼顾现有 UI 展示与新结构化诊断能力。

## 风险与回滚
1. 风险：低到中。主要影响失败分支的数据结构扩展。
2. 回滚：可整笔回滚本阶段，不涉及数据库迁移。

## 效果感知
1. 工具失败链路从“纯文本错误”升级为“文本 + 结构化契约”。
2. Agent observation 可直接消费 `error_contract` 做统一错误展示与统计。
