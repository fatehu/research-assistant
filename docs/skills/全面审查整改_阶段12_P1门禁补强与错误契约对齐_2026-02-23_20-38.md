# 全面审查整改 阶段12：P1门禁补强与错误契约对齐

## 时间
- 2026-02-23 20:38

## 目标
- 修复 E2E 在限流场景下的误报失败问题（429 无重试）。
- 补强 `check_contract_alignment.py`，将后端模型与迁移状态映射纳入校验范围。
- 统一后端 `AppServiceError` 错误体结构，并增强前端错误解析兼容性。

## 实施内容
1. E2E 脚本增加 429 退避重试
- 文件：
  - `e2e/remaining_modules_api_smoke_e2e.ps1`
  - `e2e/role_route_smoke_e2e.ps1`
- 变更：
  - 新增重试参数：`MaxRetryAttempts`、`RetryBaseDelaySeconds`
  - 429 时优先读取 `detail.retry_after_seconds`，其次读取 `Retry-After`，最后指数退避
  - 输出重试日志，避免“静默重试”

2. 合约门禁补强（后端模型 + 迁移脚本）
- 文件：
  - `backend/checks/check_contract_alignment.py`
  - `backend/tests/test_contract_alignment_check.py`
- 变更：
  - 新增校验输入：`backend/app/models/knowledge.py`、`backend/app/models/literature.py`、`backend/alembic/versions/017_status_normalization_and_conflict_cleanup.py`
  - 新增提取函数：
    - `extract_enum_members_from_class`
    - `extract_case_targets`
  - 新增规则：
    - 后端状态枚举必须可被前端 `normalizeTaskStatus` 映射
    - 017 迁移状态目标值必须属于对应后端枚举集合

3. 错误契约对齐（后端 + 前端）
- 文件：
  - `backend/app/core/errors.py`
  - `backend/app/core/error_handlers.py`
  - `backend/tests/test_app_service_error_contract.py`
  - `frontend/src/services/api.ts`
- 变更：
  - `AppServiceError` 输出统一为 `{code, message, details, request_id}`
  - 保留 `extra` 字段作为兼容来源（迁移期）
  - 错误处理器自动补齐 `request_id`（优先入参，其次请求头，最后生成 UUID）
  - 前端拦截器支持两类错误体：
    - `detail` 包裹型
    - 顶层 `{code,message,details,request_id}` 型

## 风险与回滚
- 风险：
  - E2E 重试会延长故障场景执行时间（可接受，换稳定性）。
  - 错误体结构调整可能影响少量直接读取 `extra` 的调用方（当前未发现实际调用）。
- 回滚：
  - 逐文件回滚本阶段改动即可，不依赖数据库迁移。

## 后续建议
