# 项目现状客观评审（2026-02-15 04:09）

## 1. 评审范围与方法
- 范围：后端 CodeLab 执行链路、安全配置链路、导师端真实数据链路、前端构建与稳定性。
- 方法：代码静态审阅 + 自动化验证（pytest/build/lint）+ 风险分级（P1/P2/P3）。

## 2. 关键结论（先结论）
- 当前状态：`可交付但未达到“高稳态”`。
- 已完成的高价值修复：CodeLab 子进程沙箱、CORS 白名单、启动建表开关、导师动态真实化、前端路由拆包。
- 仍存在的主要短板：沙箱隔离边界仍是“进程级”、执行链路裸 `except` 过多、前端仍有 12 条 hooks 依赖告警、核心包体积偏大。

## 3. Findings（按严重度排序）

### P1-1 沙箱仍非容器级/内核级隔离，属于“弱隔离”
- 现状：`CodeLabExecutor` 通过 `subprocess.Popen([sys.executable, ...])` 启动同宿主环境子进程，不是独立容器/微 VM。
- 证据：
  - `backend/app/services/codelab_executor.py:451`
  - `backend/app/services/codelab_executor.py:452`
- 风险：若出现 Python 运行时/第三方库逃逸路径，攻击面仍在同一容器与同一权限边界内。
- 建议：下一阶段引入真正强隔离（独立容器运行时 + 资源限额 + 网络/文件系统策略）。

### P1-2 执行链路存在较多裸异常捕获，故障可观测性不足
- 现状：CodeLab 路径中大量 `except:` / `except Exception:` 直接吞错或降级处理。
- 证据（示例）：
  - `backend/app/api/codelab.py:197`
  - `backend/app/api/codelab.py:208`
  - `backend/app/api/codelab.py:395`
  - `backend/app/services/codelab_executor.py:217`
  - `backend/app/services/codelab_executor.py:500`
- 风险：真实故障与策略绕过信号可能被淹没，线上排障成本高。
- 建议：统一错误码 + 结构化日志（错误类型、request_id、notebook_id、user_id、phase）并减少裸捕获。

### P2-1 用户并发限制是进程内计数，多实例部署会被绕过
- 现状：并发限制使用进程内全局字典+锁实现。
- 证据：
  - `backend/app/api/codelab.py:549`
  - `backend/app/api/codelab.py:550`
  - `backend/app/api/codelab.py:557`
- 风险：当后端横向扩容（多 worker / 多副本）时，限流不再全局生效。
- 建议：迁移为 Redis 分布式令牌桶或分布式 semaphore。

### P2-2 时间 API 仍使用 `datetime.utcnow()`，存在升级兼容风险
- 现状：多个关键路径仍调用已发出弃用警告的 API。
- 证据：
  - `backend/app/api/codelab.py:115`
  - `backend/app/api/codelab.py:518`
  - `backend/app/api/mentor.py:139`
- 风险：未来 Python 版本升级后维护成本增加，时区语义不够显式。
- 建议：统一替换为 timezone-aware UTC 时间写法。

### P2-3 前端 hooks 依赖告警未清零，存在闭包陈旧风险
- 现状：全量 `eslint` 仍有 12 条 `react-hooks/exhaustive-deps` warning。
- 证据（示例）：
  - `frontend/src/pages/admin/UsersPage.tsx:73`
  - `frontend/src/pages/knowledge/SmartChunkingPage.tsx:234`
  - `frontend/src/pages/shared/SharedResourcesPage.tsx:144`
  - `frontend/src/pages/team/TeamPage.tsx:62`
- 风险：状态与副作用错位，可能触发偶发性 UI 行为不一致。
- 建议：按页面逐个收敛告警到 0，再恢复严格 lint 门禁。

### P3-1 前端拆包已做但主包仍偏大
- 现状：构建产物仍有大 chunk 警告，`vendor-antd` 与主 `index` 包体积较大。
- 证据：
  - 配置入口：`frontend/vite.config.ts:42`
  - 动态导入冲突点：`frontend/src/components/layout/MainLayout.tsx:257`
- 风险：低带宽/冷启动场景首屏性能仍受影响。
- 建议：继续拆分重组件、减少 `api.ts` 混合静态/动态导入、按业务域拆 store/service。
