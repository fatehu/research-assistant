# 混合检索测试记录（2026-02-12）

## 1. 目标
- 实现混合检索：`向量检索 + 全文检索`
- 使用 RRF（Reciprocal Rank Fusion）融合两路召回排序
- 与现有 reranker 兼容：支持 `混合检索 -> reranker 精排`

## 2. 方案权衡（BM25 vs PostgreSQL 内置全文检索）

### 2.1 备选方案
- BM25（如 Elasticsearch/OpenSearch/Whoosh）
- PostgreSQL 内置全文检索（`to_tsvector` + `websearch_to_tsquery` + `ts_rank_cd`）

### 2.2 评估维度
- 部署复杂度
- 运维成本
- 与现有 PostgreSQL/pgvector 一体化程度
- 当前项目改造成本与交付速度

### 2.3 最终选择
- 采用 PostgreSQL 内置全文检索。
- 选择理由：
  - 不引入新基础设施，沿用当前 PostgreSQL 部署；
  - 可与 pgvector 查询在同库内协同，易于联调；
  - 能快速落地混合检索并保持可维护性。
- 说明：后续若数据规模和检索负载显著增长，再评估引入独立 BM25 引擎。
