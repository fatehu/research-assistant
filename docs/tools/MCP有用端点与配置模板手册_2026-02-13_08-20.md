# MCP 有用端点与配置模板手册（2026-02-13 08:20）

## 1. 目的
为当前项目整理一套“可直接落地”的 MCP 端点与配置模板，覆盖：
- 内部服务（自研、可控、可审计）
- 外部增强服务（搜索、抓取、代码仓协作）
- 双路策略（external -> internal fallback）

## 2. 当前项目支持的配置方式
当前后端支持两种配置来源（有优先级）：
1. `MCP_SERVERS`（环境变量，优先级更高）
2. `MCP_CONFIG_PATH` 指向的 JSON 文件（如 `backend/mcp_servers.json`）

注意：
- 如果 `MCP_SERVERS` 非空，会覆盖文件配置。
- 目前不会自动展开 `${ENV_VAR}`，模板中的占位符需要你手动替换成真实值。

## 3. 推荐 MCP 端点（按实用性）

| 端点 | 主要能力 | 适配你项目的价值 | 鉴权 |
|---|---|---|---|
| `web_internal` | 基础搜索/网页抓取 | 兜底链路，内部可控 | 无 |
| `literature_internal` | 文献检索 | 科研问答稳定底座 | 无 |
| Exa MCP | 语义搜索、研究检索、代码上下文 | 明显增强 `web_search` 质量 | Exa API Key |
| Firecrawl MCP | 深度抓取、抽取、crawl | 明显增强 `web_scrape` 成功率 | Firecrawl API Key |
| GitHub Remote MCP | 仓库检索/协作自动化 | 研发场景增益高 | GitHub Token |
| Brave MCP（可选） | 备用 Web 搜索 | 给 Exa 增加平行冗余 | Brave API Key |

## 4. API Key 准备清单
1. Exa API Key：见 Exa 官方 MCP 文档（Quickstart / Authentication）。
2. Firecrawl API Key：见 Firecrawl 官方 MCP 文档（Get your API key）。
3. GitHub Token：建议 PAT（最小权限原则）。
4. Brave API Key：在 Brave API Dashboard 订阅并创建。

## 5. 模板目录（本次已提供）
- `docs/tools/templates/mcp_servers.internal.json`
  - 仅内部服务，最稳。
- `docs/tools/templates/mcp_servers.external_http.basic.json`
  - 仅外部增强（Exa + Firecrawl + GitHub）。
- `docs/tools/templates/mcp_servers.hybrid.external_first.json`
  - 外部优先 + 内部兜底（推荐）。
- `docs/tools/templates/mcp_servers.stdio.reference.json`
  - stdio 参考模板（需要 Node/npx 运行环境）。
- `docs/tools/templates/mcp_servers.env_list.json`
  - 适配 `MCP_SERVERS` 环境变量的数组格式。
- `docs/tools/templates/env.mcp-routes.external-first.example`
  - `MCP_TOOL_ROUTES` 双路策略示例。

## 6. 推荐落地顺序
1. 先用 `mcp_servers.internal.json` 保证可用。
2. 再切到 `mcp_servers.hybrid.external_first.json`，填入真实 API Key。
3. 执行 `/api/mcp/status/refresh`，确认外部服务可达。
4. 观察实际对话中 `web_search`/`web_scrape` 成功率与结果质量。

## 7. 关键风险与建议
- 不要把真实 API Key 提交到 Git。
- 外部端点要配超时、重试、熔断（你项目已具备路由层参数）。
- Firecrawl/Exa 的实际工具名以 `状态刷新` 发现结果为准，再写入 `MCP_TOOL_ROUTES`。
